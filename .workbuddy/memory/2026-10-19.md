## 线上 500 事故：Worker 缺 `R2_PUBLIC_BASE`（个人中心全挂）

- 现象：线上 `/account` 的 tab 全部「载入失败」，`/api/user/profile` 等接口 500 且**响应体为空**；本地正常。
- 定位（只读探针，用本地 `SESSION_SECRET` 签一张前台会话 + D1 REST 只读查询）：
  - `GET /api/user/profile` 对**无头像**账号 200、对**有头像**账号 500 → 差异只在 `toAppUser()` 调 `publicUrl()`。
  - `GET /api/games/<id>/comments` 直接把真相吐出来：`{"error":"list-failed","detail":"R2 未配置：缺少 R2_PUBLIC_BASE"}`。
  - 链式后果：`publicUrl` 抛 → `assertUser` 里 `getAppUser` 跟着抛（在 try 之外）→ **每个 `/api/user/*` 都空 500**（收藏/历史/存档/资料四个 tab 一起挂）；生产上 `SITE_URL` 的 sitemap/canonical 正常 ⇒ 变量机制本身没问题，**就是这一个变量没配**。
  - 同一根因还打死 `GET /api/games/<id>/rom`：**20 款「只有 rom_url、无 source_url」的游戏**（即 R2 直链那批）线上 500，玩不了。
- 改动：
  - `lib/server/r2.ts` 抽出 `joinPublicUrl()`；新增**软版** `publicUrlOrNull()`（缺 base 回 null，不抛），`publicUrl()` 保持严格。
  - `app-users.ts` 的 `toAppUser`、`comments.ts` 的 `toComment` 改用软版 —— 头像是展示字段，拼不出来最多画默认头像，**不能再连累整条请求 / 守卫**。
  - `wrangler.jsonc` 的 `vars` 补 `R2_PUBLIC_BASE=https://games.retrogamesonline.fun`（非机密，跟 SITE_URL 一样进配置，免得下次发版又丢）。
- 待用户做：重新部署（或仪表盘补这个变量）；顺带确认 R2 的 ENDPOINT / BUCKET / KEY 三个**配置变量**在线上还在（头像上传走它们）。
- 校验：`tsc --noEmit --incremental false` 只剩既有 4 条 `open-next.config.ts` 依赖缺失；`eslint` 三个改动文件 0 条。
