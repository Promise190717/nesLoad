## 线上 PS1 几乎全部打不开：根因是 ROM 代理传不了大文件（2026-10-19 定位）

- 现象：`/zh/consoles/ps1` 的 460 款里基本都开不了。
- 复现（本机 Chrome 无头 + 线上真实 `/zh/play?id=`）：296MB 的 `disney-tarzan.chd` 到手只有 **7,900,864 字节** ⇒ `checkChdIntegrity` 判 `truncated` ⇒ `载入失败: IncompleteRomError`。小文件（25MB `captain-tsubasa.pbp`）能正常起核。
- 直接量 `/api/games/<id>/rom`：整包 GET 反复只给 **1–3MB**（`http=200`，chunked，无 `Content-Length`）；`Range: bytes=0-4999999` 直接 **503 `error code: 1102`**（Worker 超资源上限）；但 1/2/4/8/16MB 的单段 Range 全部完整、且 **4 路并行 8MB 分片 19s 走完 32MB**。
- 上游 `files.retrogamesnexus.com` 直连同一文件 **296MB/383MB 全量正常**（2.5–4MB/s）⇒ 问题不在上游、不在 R2、不在核心/格式（`pcsx_rearmed` wasm 里有 `bin|cue|img|mdf|pbp|toc|cbn|m3u|chd|iso|exe`，BIOS 可回落 HLE）。
- 数据形状：PS1 460 款 = zip 245 / chd 131 / 7z 57 / pbp 22 / bin 2 / iso 2 / cnd 1（`cnd` 是错扩展名），全部 `files:` 走上游代理；抽样 12 个 chd 结构自检全 `ok`，**不是坏盘**。
- 结论：Cloudflare Worker 单请求搬不动 100MB+（约 50–60s / 100MB 量级的天花板），PS1 盘天生 200–780MB ⇒ 必然挂。同一条路 65MB 的 NDS 能过（44s），111MB 的直接 1102。
- 待定方案（用户选）：A 分片 Range 下载（纯前端，300MB 约 2–3 分钟）；B ROM 搬 R2 + 给 `games.retrogamesonline.fun` 配 CORS、前端直连（PS1 约 140GB ≈ $2/月）。

## 兜底修复：ROM 改走分片 Range 下载（`fetchRomWithProgress`）

- 用户选了「先加分片下载兜底」，没动基础设施。
- 新增 `lib/http.ts` 的 `fetchRomWithProgress(url, {signal, onProgress})`：第一片兼探针（`Range: bytes=0-8388607` 拿 `Content-Range` 问总长，服务器不认 Range 就**原样退回** `readBodyWithProgress`）；之后 3 路并行按 8 MiB 切片；每片核对字节数，失败重试 3 次（退避 250ms→2s 封顶），**还不行就把这段对半切开再要**（下限 512 KiB / 4 层）—— 截断的本质是「搬到一半就断」，段短就过得去。

  - 92.8 MB pbp → 43s 全量、头 `00 50 42 50`；
  - **296.9 MB `disney-tarzan.chd` → 117s 全量、头 `4d 43 6f 6d 70 72 48 44`（MComprHD）**。
  - 同期线上分片失败率很高（8 MiB 串行 8/8、15 次里 6 次坏），**靠重试 + 对半切才稳**；所以 8 MiB 是「正常时一片能过」，不是「永远能过」。
