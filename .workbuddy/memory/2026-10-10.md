## SEO 层（当天下午）

用户原话：「给这个站增加一些 seo 相关的吧 标题 desc 啥的」，并明确了**站点定位**：
**主要用来玩复古游戏**（NES / SFC / 街机），有**在线游戏库**，**自己的 ROM 文件也能跑**。
SEO 文案全部按这个定位写，这个定位也是后续写 marketed 文案的基调。

新增文件：

- `lib/site.ts` —— 站点源的唯一出口（`SITE_NAME` + `resolveSiteOrigin()`）。
  取源顺序：`SITE_URL` → `NEXT_PUBLIC_SITE_URL` → `VERCEL_URL` → 请求头 Host → localhost。
  ⚠️ 里面那句 `await headers()` **故意不包 try/catch**（理由写在文件里）：
  包了会把 Next 的 DynamicServerError 吞掉，robots/sitemap 会被预渲染并永久烤上 localhost。
- `lib/server/locale.ts` —— `readLocale()` 从 app/layout.tsx **搬**过来的（后台也要用），
  所以 layout 里那段 `cookies()/headers()` 代码已删、改为 import。
- `lib/og-image.tsx` + `app/opengraph-image.tsx` + `app/twitter-image.tsx` ——
  用 `next/og` 的 ImageResponse **现场画** 1200×630 分享图（不往仓库塞 PNG）。
  **没用像素字体**（Satori 拿不到页面 CSS 字体，fetch ttf 会把分享图绑上外部依赖）；
  **图上只有英文**（默认字体无汉字）。已在浏览器里看过成图，正常。
- `app/robots.ts`、`app/sitemap.ts` —— 都带 `export const dynamic = 'force-dynamic'`
  （`<loc>` / Sitemap 行要绝对地址，必须请求期现算）。robots 挡 `/admin` 与 `/api`。
- `app/admin/layout.tsx` —— 纯透传 layout，只为给整个 /admin 子树挂 `noindex,nofollow,nocache`
  + 跟语言走的标题（`后台 · nesLoad`）。

改动的文件：

- `app/layout.tsx` —— `generateMetadata` 补全：metadataBase、title.default + template、
  description、keywords、applicationName / authors / creator / publisher / category、
  canonical、formatDetection、openGraph（**不写 images**，交给文件约定）、
  twitter（summary_large_image）、robots（含 googleBot 的 max-*）。

## 站点改名：nesLoad → 复古游戏屋 / Retro Game House（同日）

用户：「网站名称不叫 nesload 叫复古游戏屋吧」。

做法：站名收进 `lib/i18n.ts` 的 `SITE_NAME: Record<Locale, string>`
（zh 复古游戏屋 / en Retro Game House），**只有这一处**。
所有出现站名的文案改用 `{site}` 占位 —— `translate()` 支持变量替换：
- 服务端：layout 的 `t()` 里传 `{ site: SITE_NAME[locale] }`
- 客户端：**I18nProvider 的 `t` 统一注入**，调用点不用手写
  （ConsoleScene 的 sr-only 正文就是这么拿到站名的）

`lib/site.ts` 里原来的 `SITE_NAME` 已删（它那支依赖 next/headers，客户端用不了；
站名要按语言取，放 i18n 更顺）。

分享图取 `SITE_NAME.en`（中文名画上去是豆腐块，见 lib/og-image.tsx）；
字号从 112 降到 76 —— "Retro Game House" 16 个字符，再大就顶破机身边框。
已重新出图看过，正常。

顺手删掉 `meta.ogAlt`（中英各一处）：**它从来没被读过**。
og:image 的 alt 由 `app/opengraph-image.tsx` 按文件约定导出，必须是静态值、
拿不到当前语言，所以只能是一句写死的英文（在 lib/og-image.tsx 的 OG_ALT）。

**没改**（这些是内部标识符，改了会让老用户数据/联机房间失联）：

cookie、`nesload_admin` cookie、`lib/netplay.ts` 的 `APP_ID`。
README 的 `# nesLoad` 标题也留着（那是仓库名，不是站名）—— 用户如果要改再说。

## 联机键位：加入者改用 1P 那组

用户问：「现在玩家一二用不同键位，联机时能都用玩家一的键位么？」—— 能，而且改动很小。

**关键认知**：联机 wire 上只传**钮名**（`ButtonMessage {b,d}`），房主那边用
`overrideInjectionKeyMap`（拿**房主启动时那份**键位）解码。加入者按了哪个物理键，
房主完全不知道、也不需要知道 → **加入者的物理布局纯属本机私事**。所以「用哪组键」
和「注入到哪个玩家位」本来就该解耦。

原先挡着的两处：`ConsoleScene` 的转发表写死查 `bindings.p2`；`KeyBindingsPanel` 把加入者
锁在 p2 页签 + `conflictInOtherPlayer` 拒绝撞键，**手动镜像 P1 也做不到**。

用户选了「直接切 1P」（否掉了「加开关」和「允许 P1 复制到 P2」两个方案）。改动：
- `ConsoleScene.tsx`：转发表 → `codeToButton(bindings.p1)`
- `KeyBindingsPanel.tsx`：`lockedPlayer = role ? 'p1' : null`（两种角色锁同一组，理由不同），
  联机时那个标签改叫「你的键位」（新键 `keybind.mine`）—— 不写「玩家 1」是因为加入者
  会读成「那是房主的键」
- i18n：`keybind.guestHint` / `guestLocalHint` 改口；顺手把 `netplay.youAreHost/youAreGuest`
  里**写死的「默认键位：…」清单删了** —— 用户改过键位后它就说假话，`playerLegend` 记过同一个坑

**没动**：房主 P1/P2 不许撞键那条校验（注入合成的是真键盘事件，同一个 code 会同时驱动两个玩家）。
**没做**（可选后续）：按键说明弹窗在房间里仍列两组，加入者看 P2 那行没用。
