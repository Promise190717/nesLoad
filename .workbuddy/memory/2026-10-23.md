# 2026-10-23

## 线上 54% 错误率定位：force-dynamic 版被发到了免费版 Workers

用户贴面板数据：版本 `09baffc1`、100% 流量、0.6 req/s、**错误率 54.1%**、**CPU 中位数 12.91ms**。
这就是 22 日傍晚那条预警（「不要把这版发到 Cloudflare，force-dynamic + 免费版 10ms = 全站 1102」）
原样发生了：中位数 12.91ms 已在中位数上越过 10ms 硬限，所以过半请求 `1102`。

用户明确否掉三条常规路：**不要 ISR、不要 Workers Paid、不要迁 Vercel**，要求纯靠优化压下去。

## 量测：每请求要 JSON.parse 的字节（Supabase 真库，临时探针，已删）

| 取数 | 改前 | 改后 |
|---|---|---|
| 列表页 15 款文案 | 244.8 KB（18 语言 270 行） | 3.9 KB（≤3 语言 30 行） |
| 列表页 15 款 ROM | 12.4 KB（44 行） | 0（不查） |
| 详情页 1 款文案 | 18.1 KB（18 语言） | 1.6 KB（≤3 语言） |
| 首页 console_texts | 47.7 KB（252 行） | 8.0 KB |
| 首页 developer_texts(top8) | 149.3 KB | 8.6 KB |

结论：**全站每请求都在为 18 种语言的白付 CPU**。文案表是 `(实体, locale)` 一行，
`loadGameTexts` / `loadConsoleTexts` / `loadDeveloperTexts` 原来一律全量捞。

## 落地：文案按「当前语言 + 回退链」裁，列表再砍字段

- `lib/game-text.ts` 新增 **`textLocalesFor(locale)`** = 自身 + `entityFallbackChain`（≤3 种）。
  不能只传自身：英文站缺字段时就不回退中文了，卡片标题会空白。
- `loadGameTexts(slugs, { locales, content })`：`locales` 加 SQL 过滤；`content: false` 时
  `description` / `controls` 直接给 `NULL`（保持行的形状，`normalizeControls(null)` 返回 null）。
- `attach(base, { locales, content, roms })`：`roms: false` 跳过 `loadRoms` + `sortRoms`
  （列表卡片没有语言角标、没有下载信息，那次查询整个白跑）。
- 列表四个 `*Cached`（page / latest / by-console / by-developer）走 `cardAttachOptions(locale)`。
- `getGame(id, locale?)`、`listConsoles(locales?)`、`listTopDevelopers(limit, locales?)`、
  `listDevelopers(..., locales?)` 全部加可选语言维；不传 = 全量（后台编辑 / 写路径要齐）。
- **缓存键尾版本全部 +1**（`sb:games:page` v2→v3、`by-id` v3→v4、`consoles:list` v8→v9、
  `developers:list` v5→v6、`developers:top` v4→v5），`locale` 进键。不升版本线上会继续读到
  18 语言的全量旧条目，优化等于没上线。
- 详情页 / 下载页 `loadGame(id)` 改成先 `readLocaleParam` 再 `loadGame(id, locale)`
  （原先是 `Promise.all` 并行，现在多一次 await，但 locale 只是解析 cookie）。

校验：`npx tsc --noEmit --incremental false` 干净；eslint 只剩基线那批（`TurnstileWidget`
的 react-hooks/refs 13 条 + `sb-games.ts` 的 CONTENT_LOCALES 未使用）。

## 没动的、以及为什么

- **`/api/games`（在线库接口）仍走全量文案**：`listGamesPage` 不传 `attachOptions`。
  ConsoleScene 是客户端组件、语言可在运行时切（`localizeLibraryGame` 现取），接口必须
  一次给足多语言。要裁得先确认它只用到 `title`（`content: false` 还能省下描述与键位表）。
- **`getGameForWrite`** 仍全量 18 语言（5 个写接口在用，其中 reports / history 会
  `localizeTexts` 存标题）。要裁得把 locale 从 cookie 带进这些路由。
- `getDeveloper` / `getConsole` 单条仍全量（长尾页面，单条 10-15KB，收益小一档）。

## 判断（要跟用户讲清的那句）

砍数据能把 12.91ms 压到 9ms 上下，**但免费版 10ms 配 Next 16 全动态渲染没有余量**：
路由 + RSC 渲染框架的固定开销本身就占 5-7ms，详情页还叠评论、结构化数据的一次库查询。
这次是「把白付的钱省掉」，不是「让 10ms 变宽」。要归零还得回到那三条路之一。

## 第二轮：真正的元凶是 `prefetch`

用户要求「再优化，压到 10ms 以内」。复查 Link 时发现：全站 91 个 `<Link>`，只有 5 处关了预取
（TopBar 账号/登录、GameComments、/games 机种 tab、机种页语言条）。**列表网格的卡片一个都没关**。

Next 生产模式下会预取「进入视口的 `<Link>`」指向的路由 —— 一页 15~24 张卡片，
等于**每来一个访客就额外渲染 15~24 次详情页 RSC**。详情页是全站最重的一页
（文案 + 收藏数 + 评论模块 + JSON-LD），免费版每请求 10ms ⇒ 这批预取请求就是
「错误率 54%」的主力，而且它们全落进 CPU 中位数里。

关掉的位置：
- `components/GameCardGrid.tsx`（15~24 张，**最大头**）
- `components/ConsoleCard.tsx`（首页 14 台机种）
- `app/[locale]/page.tsx` 开发商 chip（8 家）
- `lib/server/pages/developers.tsx` 开发商卡（一页 24 家）

保留预取：顶栏、返回、翻页、hero 的「开始游戏」这类**每页只有一两个**的链接 ——
预取的价值在即时跳转，几十个一起预取就变成纯成本。

## 第二轮顺带

- `getConsole(type, locales?)` / `getDeveloper(id, locales?)` / `getConsolePageData` /
  `getDeveloperPageData` 也按语言裁；`loadConsole` v2→v3、`loadDeveloper` v3→v4。
- `lib/i18n.ts` 的 `formatTime` 改成**按语言标签缓存 `Intl.DateTimeFormat` 实例**：
  原来是每次调用都 new（构造要初始化该语言的 ICU 日期数据，Workers 里是毫秒级），
  存档 / 收藏列表几十行就是几十次。

## 明确没动的（查过，动不了）

- **`/api/games` 必须保留全量文案**：`GameLibraryPanel` 真的用了 `text.description`
  （776 / 928 行），客户端又能在运行时切语言，接口不裁。它默认 limit=15 ⇒ 每次 245KB。
- **`getGameForWrite`** 仍全量：reports / history 用 `localizeTexts` 存标题。
- **`enableCacheInterception`** 不能关：sitemap / robots / llms.txt / ai.txt 四条路由缓存靠它，
  关了 sitemap 每次现拼 7.2 万条 `<xhtml:link>`，比省下的那点更贵。
- **i18n 的 18 个语言文件（≈1MB）全静态 import**：影响的是 isolate 启动而不是请求 CPU，
  改成动态 import 要让 `translate()` 变异步（558 键遍布全站），不可行。低流量（0.6 req/s）
  下 isolate 回收频繁，冷启动可能仍是尾部延迟的一部分 —— 这条只能靠付费版或迁走。
