## 右侧按钮组（rail）图标细线在 2K 及以下屏看不见 —— 修好了

**现象**（用户）：右侧那排开关的图标「在 2k 及以下显示器上显示效果不好，很多细线都看不到」。

**根因**：`icons.tsx` 的图标是 `viewBox="0 0 16 16"`、用整数坐标 **1 单位宽的 `<rect>`** 拼的
像素画，配 `shapeRendering="crispEdges"`；但调用处传的是 `size={13}` ⇒ 缩放比 **13/16 = 0.8125**。
在 **DPR = 1** 的显示器上（2K / 1080p 桌面屏基本都是 100% 缩放）每根线只剩 0.8125 物理像素，
crispEdges 吸附后很多 1px 空心边被吃没 / 变淡。DPR ≥ 1.5 的屏（4K 高缩放）物理像素够多，所以只在
2K 及以下露馅 —— 和用户描述完全吻合。

**铁证**（说明这是「改漏了」，不是设计如此）：`RailDivider` 是 `w-7`（**28px**），ConsoleScene 里
「联机」那颗钮的注释也写「每个按钮才 **28px** 宽」——而 13px 图标 + p-1.5(6×2) = **25px**。
也就是说这列按钮**原始设计就是 16px 图标 + 6px 内边距 = 28px**，13px 是后来某次改小、漏改了分隔线。

**改法**：把图标渲染尺寸改回 **16**（= viewBox，1 单位 = 1 物理像素），按钮自然回到 28px，
分隔线 `w-7` 重新对齐。
- `components/ConsoleScene.tsx`：11 处 `size={13}` → `size={16}`
- `components/icons.tsx`：12 个图标默认值 `size = 14` → `16`；顶部加了一段「size 必须 = viewBox 的
  16（或整数倍），别传 13/14」的约束注释
- `app/globals.css`：`.theme-toggle` 注释（13/25 → 16/28）、`.locale-toggle` 的
  `min-width: 25px → 28px`、`line-height: 13px → 16px`

**当时没做**：第一轮只把渲染尺寸改回 16，没把 1px 线加粗 —— 用户随后就反馈「还有很细的线条」，
所以当天又做了第二轮（见下）。

**验证**：`pnpm typecheck` 通过；`pnpm lint` = 364 problems (15 errors, 349 warnings)，与基线一致。
**未实测**（用户要求不主动测），交给用户自己看。

## 补：下载不该起顶栏进度条（用户反馈「下载的时候也触发这个顶部的进度条了」）

根因：`nextjs-toploader` 的 click 代理挂在 `document` 上，**任何同源 `<a>` 点击**
它都 `start()`（源码里那条白名单只放行 `target` 非空 / tel: mailto: sms: blob: /
hash / 带修饰键 / 非 http —— 它**不看 `download` 属性**），然后等 `pushState` 来收尾。
下载不换页 ⇒ 收尾永远不来 ⇒ 条挂死在 99%。

改法：新 `lib/download.ts` = 「把文件甩给浏览器」的唯一出口，`downloadFile(source, filename)`
接受同源地址或 Blob；造链后**在链上挂 `click` → `stopPropagation()`**，让 `document`
收不到这一下（默认行为不受影响，文件照下）。两个调用点改走它：
`components/RomDownloadGate.tsx`（原来手写 `<a>`）、`lib/emulator.ts`（原私有
`downloadBlob` 已删）。**没用**「让它起再 `done()`」—— nprogress 的 `done()` 是从
当前位置扫到 100% 再淡出，等于一条横穿屏幕的亮条，与初衷相反。

验证：全量 typecheck 仍是 2 个 `.next/types` 残留错（与我无关）；lint 544(20/524)
**与上一轮一模一样**，我改的三个文件 0 条。未实测。

- **一层三颗降一档**：`py-2.5`+`13px`+`gap-2.5` → **`py-2`+`12px`+`gap-2`**，
  即站内**紧凑钮**标准档（AdminGames / GameLibraryPanel / NetplayPanel 里那批钮都是它）。
  原来那档比全站任何一颗钮都大一号 —— 单看还行，摆在页面里反倒笨。
  宽度：开始游戏 `px-6`→`px-5`（仍是三颗里最宽的），收藏/下载 `px-4`→`px-3.5`；
  钮内图标间距 `gap-2`→`gap-1.5`，`▸`/`↓` 字号 `11px`→`10px`（跟着字号降一档，
  不然小钮里那个符号会顶出来）。
  ⚠️ 这三颗**必须同档**：`FavoriteButton` 是独立组件，改它时得和页面里那两颗对齐，
  谁大一点都会把这排拆成「一颗主钮 + 两颗陪衬」。
- **二层拉开**：`mt-3`（12px）→ **`mt-6`（24px）**。12px 时那行分享/反馈看着像
  黏在一层按钮上的尾巴；24px 之后才读得出「这是另一组东西」。选 24 而不是更大的值，
  是因为 24px 正是**这一页的段落间距**（下面正文、资料表都是 `mt-6`），
  拉开之后整页纵向节奏一致。
- 否掉的：给二层再加个细分隔线/浅底把它「框成一块」—— 那等于把刚拆掉的钮身又装回来。
- i18n 未动；未实测（用户要求）。lint：改的 2 个文件 0 条；typecheck 仍只有
  `.next/types` 那 2 条陈旧错。

### 补充二：一层三颗的图标字号 10px → 15px

用户原话：「这仨个按钮前面的图标都太小了 加大点」。

- **钮缩小 ≠ 图标跟着缩**：上一轮我跟字号一起把 `▸`/`↓` 从 11px 降到 10px，降错了；
  收藏那颗的 `★/☆` 更是**一直裸着**（没写尺寸，拿到 12px 正文字号）。
- 现在三处统一 **`text-[15px] leading-none`**：`▸`（开始游戏）/ `↓`（下载 ROM）
  在 `page.tsx`，`★/☆`（收藏）在 `FavoriteButton.tsx`。**三颗必须同尺寸** ——
  一行里三个符号三种重量，比都小还难看。
- 为什么是 15 而不是 16：站内 svg 图标（`icons.tsx`）一律 `size=16` 配 12px 字，
  而 `▸ ★` 是**实心字形**，视觉上比 16px 的细线图标重，所以收 1px 对齐观感。
- ⚠️ `leading-none` 必须留着：它让符号自身的行高 = 15px **小于**文字那 18px 的行高，
  所以放大符号**不会把钮撑高**（`items-center` 负责居中）。
  去掉它的话 15px 的 line-height:normal 会变成 ~17.5px，仍然不撑，但别去赌。
- 未实测（用户要求）。lint：改的 2 个文件 0 条。
  typecheck：全量只剩 `.next/types` 那 2 条陈旧错。
  （中途跑出过一次 `components/GameComments.tsx` 缺 `comments.rating*` 一堆 key ——
  那是**并行进程**正在加评论星级，下一轮就补齐了，不是我这轮改出来的。）

## 评论加星级 1-5（2026-10-13 用户要求「评论有星星1-5 字段没有的话你就增加」）

- 表 `game_comments` 加 `rating INTEGER NOT NULL`（和正文同一条记录，无「只打分不写字」通道）。
  · `db/schema.sql` 与 `scripts/add-game-comments.mjs` 的建表语句**同步改了**（脚本比对过，逐字一致）。
  · **老库要 ALTER 补列** ⇒ 新脚本 `scripts/add-game-comments-rating.mjs`
    （`ADD COLUMN rating INTEGER NOT NULL DEFAULT 5`；先 PRAGMA 判存在所以幂等；已对真库跑过 —— 当时表里 0 行，
    没有老评论被记成 5 星；再跑一遍验过幂等）。
  · **刻意不写 CHECK(rating BETWEEN 1 AND 5)**：老库那列是 ALTER 补的、SQLite 加不了约束，
    给新库写 CHECK 就出现「新库拦得住老库拦不住」。校验只在 `POST /api/games/[id]/comments`
    （`Number.isInteger` + 1..5，常量 `RATING_MIN/RATING_MAX` 出在 lib/server/comments.ts）。
- 数据层：`Comment.rating` / `CommentRow.rating` / SELECT 带 `c.rating` / insert 带 rating；
  新增 `getGameRatingSummary(gameId)` = `AVG(rating), COUNT(*) WHERE game_id=?`。
  ⚠️ **它必须单独一条全量查询**，不能拿 listGameComments 那一页算 —— 分页会让均分随「加载更多」往下掉。
  走 `idx_game_comments_game` 前缀，没加新索引。
- 接口：GET 响应加 `summary: { average, count }`（跟列表一起回来，首屏不用多发一次请求）；
  POST 校验 rating 必填 1..5（错误码 `rating-invalid`）并落库。
- UI（`components/GameComments.tsx`）：发表框里**星在正文上方**（先说几分再说为什么），
  **默认 0 颗**（不预设 5 星 —— 「忘改」和「真给 5 星」就分不开了），不选只吃一句「先给个星数吧」
  （和「写点什么再发表吧」同路，不把按钮变灰）；悬停/聚焦有预览高亮。
  列表每条的星挂在**用户名后面**（`'★'.repeat()` + 空心补位，夹了上下界；图形 aria-hidden、分数走 sr-only）。
  标题改成 `★ 4.3 / 5 · N 条评论`（全量 summary，不再受「全部载完才敢报」的限制；**不画半星**）。
  发表 / 删除后 `shiftSummary(summary, rating, ±1)` 按总分回推均分，**乐观挪一格**；删除失败连汇总一起回滚。
- i18n：`comments.ratingLabel / ratingStar / ratingValue / ratingAverage / ratingRequired` 中英各一份。
- 未实测（用户要求）。`tsc --noEmit --incremental false` 只剩 `.next/types` 那 2 条陈旧错（同基线）；
  改动的 4 个文件 eslint **0 条**。

### 星的形状来回（同一天，接着上面）

- 用户报「为什么英文下**星星还是小的**」→ 查清根因：星是 `★` 字符（U+2605），
  页面主字体**没有**这个字形 ⇒ 浏览器**按文档语言挑兜底字体**：`lang="zh-CN"` 落到中文字体
  （全角、撑满 em 框），`lang="en"` 落到西文/符号字体（同字号只画一小团）。
  排过因：全站没有 `:lang()` / `[lang=]` 规则、也没用 next/font，`<html lang>` 是唯一变量。
  ⚠️ 所以「把 `font-size` 调大」治不了根。
- 第一版解法（已撤）：在 `icons.tsx` 写了 `StarIcon` —— 8×8 网格的**实心像素星**，渲染尺寸取
  8 的整数倍（16 / 24 / 32）保证整像素；发表框 24px、列表 16px，中英文彻底一致。
  用户反馈「怎么改成**马赛克**形式了 改回去」⇒ **当天撤掉**（图标 + 三处调用全部还原成字符版）。
- 最终解法：`app/globals.css` 加 **`.star-glyph`** 字体栈，把 CJK 字体（Microsoft YaHei /
  PingFang SC / Hiragino Sans GB / Noto Sans CJK SC …）排在最前 —— 两种语言都会挑到同一个字体，
  大小才一致；栈尾再兜 'Segoe UI Symbol' / 'Apple Symbols'。发表框（18px）、列表每条、
  标题那颗 ★ **三处都加了**这个类。
  ⚠️ 它的局限：跨机器仍依赖本机装了哪些字体（真正跨机器确定只能画成图形，而图形被否了）。
  以后再遇到「中英文同一处大小不一致」，先怀疑**字符的兜底字体**。
- 顺带还原：标题行 `items-center` 改回 `items-baseline`（那行改动只是为了让图形对齐，图形撤了就没必要）。
- 没动的地方：收藏钮那对 `★ / ☆`（`FavoriteButton`）也有同一个毛病，用户没提，已在回复里问要不要一起换。
- 未实测（用户要求）；`tsc --noEmit --incremental false` 仍只剩 `.next/types` 那 2 条陈旧错，eslint 0 条。
