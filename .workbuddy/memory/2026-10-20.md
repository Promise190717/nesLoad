## 🔴 线上全站 500：Worker 里跑不了裸 TCP（数据层改回 HTTPS）

用户报「所有接口都 500，列表页也报错」。实测线上：`/api/games` → `list-failed` 500，
`/api/games/<id>` → `lookup-failed` 500，`/api/user/history` 未登录是 401（守卫本身不读库）、
登录后 500；首页 200 但是 `x-opennext-cache: HIT` 的旧缓存。⇒ 缓存命中正常，凡是要实时读库的全挂。

根因（不是 SQL）：**Cloudflare Workers 里没有可用的裸 TCP + TLS**，而数据层当天刚改成
`postgres`（porsager）直连 Supabase pooler。探针实测（workerd）：
- `node:net` 的 `connect()` 能连上（也验证过原生 `cloudflare:sockets` 读到 SSLRequest 回的 'S'）；
- `tls.connect({ socket })` 报 secureConnect 成功，**写第一条 PG 报文就 `Network connection lost.`**；
- postgres.js 默认还会传 `rejectUnauthorized: false`，Workers 的 `node:tls` 直接抛
  「The options.rejectUnauthorized option is not implemented」；`ssl:{}` 也救不回来。
（本地 `wrangler dev` 与 `postgres` 直连都正常，所以属于典型的「本地通、线上炸」。）

改法：`lib/server/pg.ts` 重写成 **HTTPS → PostgREST → `public.exec_sql`**。
- 函数（`db/schema.pg.sql` 末尾）收一句 SQL、返回 jsonb 数组；`with __r as materialized (...)` 包一层，
  `materialized` 是必须的（不加会被内联，`order by … limit` 顺序不保）；不带 RETURNING 的写语句
  命中 `RETURNING clause` 异常时裸跑一遍。
- 权限：`security definer` + `revoke from public/anon/authenticated` + `grant to service_role`。
- `bindParams()` 取代 `toDollarPlaceholders()`：扫一遍 SQL，把 `?` 就地换成转义字面量
  （字符串 `''` 转义；数字/布尔/null；其余类型抛错）。参数内容不再被二次扫描，天然防注入。
- `transaction()` / `isPgConfigured()` / `closePg()` 已删（都无调用方）；`postgres` 只剩 `scripts/*.mjs` 在用。
- 副作用：Worker 产物不再带 postgres.js；`SUPABASE_DB_URL` 应用不读了，`SUPABASE_URL`（wrangler vars）
  + `SUPABASE_SECRET_KEY`（secret）变成硬依赖，**构建期预渲染也要**（首页会读库）。

验证（用 npx tsx 直跑真实数据层函数，跑完删掉探针）：listGamesPage / countGames / getGame / getGameRoms /
loadGamesBySlugs / listConsoles / getConsole / listDevelopers / getDeveloper / listTopDevelopers /
listDeveloperOptions / countGamesForDeveloper / 用户三件套（history/favorites/saves 空表）/
listGameComments / getGameRatingSummary / listFeedback 全部正常；排序保持；无 ISO 时间串泄漏
（时间列都已在 SQL 里 `extract(epoch…)*1000`）；无 RETURNING 的 INSERT 走裸跑分支且不吞真错误
（`relation "nope_table" does not exist` 照旧抛出）；`select ?::text` 传 `it's ? a test` 正确往返。
一页 15 款带 18 语言文案 ≈ 181KB / 3 次往返（本地经代理 2.5s，Cloudflare 侧会低很多），页面有 30 天 ISR 兜着。
