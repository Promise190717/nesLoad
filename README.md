# nesLoad

在浏览器里运行的 NES / SFC 卡带加载器。界面是一台极简像素风的电视机：把 ROM 文件拖到机身上（或点机身下沿的插卡口），卡带就会插进去开始运行。

模拟内核基于 [Nostalgist](https://nostalgist.js.org/)（封装 RetroArch 的 WASM 构建）。NES / SFC 的核心在运行时从 CDN 加载；**街机（FBNeo）的核心随仓库放在 `public/cores/`**，从本站加载、不走 CDN。**仓库内不包含任何 ROM**——`public/cores/` 里是开源的 WASM 核心构建，不是 ROM。

## 界面与操作

界面只有两个东西：**电视机**和机身下沿的**插卡口**。载入游戏有三种方式：

1. 把 `.nes` / `.sfc` / 街机 `.zip` 文件直接拖到电视机上（街机的 `neogeo.zip` 也走这条路，见「支持的格式」）；
2. 点机身下沿的插卡口，在文件选择框里挑；
3. 点右上角的**游戏库**图标，从弹窗里挑：在线库直接下载，「历史」里是这台机器上载入过的卡带。

卡带插进去以后只露出**侧面那一条**——就是真实卡带插进机器后你能看到的那一面，名字沿长边走。点前面板的「弹出」把它取出来。

前面板上还有一组音量档位（`VOL`）：六格代表六档，点第 n 格就是第 n 档，两端的 `−` / `+` 微调，`−` 按到底即静音（六格全暗）。档位记在 `EmulatorController` 里，所以还没插卡带时调也有效，插上时作为初值生效。

相邻两档差 **6 dB**，1 档到 6 档一共 30 dB。间距刻意取这么大：原先的 4 dB 会被当成「按了没反应」。最大档也**不是**原音量，而是比 RetroArch 的默认满音量（0 dB）低 6 dB —— 0 dB 在浏览器里放 NES 游戏明显偏吵。运行时音量靠 `VOLUME_UP` / `VOLUME_DOWN` 一条条补（RetroArch 每条只走 0.5 dB，而且没有 SET_VOLUME），所以跨一档要发 12 条命令。

面板右侧那排是存档相关的按钮：**存档**写一份新快照，**读档**浮出存档列表，**导入 / 导出**走 `.state` 文件，**弹出**把卡带取出来。

### 游戏库 / 历史

右上角那个**游戏库**图标点开是个全屏弹窗，里面两个 tab：

- **游戏库** —— 后台上传到 R2 + D1 的游戏，网格排封面，点一个把 ROM 拉回来直接插进卡槽。ROM 走本站代理（`/api/games/[id]/rom`），下载进度叠在封面底部那一条上。
- **历史** —— 这台机器上载入过的卡带。载入过的 ROM 会原样存进 IndexedDB（存 Blob，不做 base64 膨胀），按最后游玩时间倒序，**最多保留 10 盘**，超出后自动淘汰最旧的一盘。行尾的 × 是移除。

> 电视机右侧那个**卡带架** 2026-10-09 撤掉了：它和「历史」是同一份数据，留两处只会分叉。架子那套「开放式立柱 + 一格一根横档」的做法连同 `CartridgeRack.tsx` 一起删了，真要找回来去 git 历史里捞。

插在机身上的那盘用 `CartridgeSprite`（标贴 + 塑料前缘两段），宽度由父容器定，插卡舱里是 359px。

### 主题与全屏

右侧竖着一排开关（上下居中贴右边，不压机身）：**夜晚 / 白天**、**语言**、**游戏库**、**全屏**、**简洁模式**、**联机**、**自定义按键**、**按键说明**。

- 主题由 `<html data-theme>` 驱动，首屏由内联脚本写入，不会闪一帧深色。浅色主题是把整条 `ink` 灰阶反过来映射，所以组件的颜色类一行都不用改。屏幕内部例外——显像管底永远是黑的，那里用一组固定的 `crt-*` 令牌。
- 全屏的是**屏幕本身**而不是整页，canvas 用 `object-fit: contain` 做等比留边。全屏后屏幕右上角会出现退出按钮。
- **简洁模式**由 `<html data-simple>` 驱动（同样由首屏内联脚本写入），点一下只留**背景墙 / 电视机 / 桌子 / 地面**，把吊灯、窗户、日历、地板杂物（含留言本和纸片）整体藏掉。状态记在 localStorage，刷新后还在。

### 键位

默认值（**可以改**，见下）：

**1P**：`W` / `A` / `S` / `D` 移动，`J` = A，`K` = B，`L` = C，`U` = X，`I` = Y，`O` = Z，`B` = 投币，`Enter` = 开始

**2P**：方向键移动，小键盘 `1` `2` `4` `5` `7` `8` = A B C X Y Z（三行各取左边两个，凑成一块 2×3），`Del` = 投币，小键盘 `0` = 开始

> 两套按键刻意不重叠，避免双人同屏时互相抢键。
>
> 右侧那排开关里的**按键说明**（问号那个）点开是个弹窗，里面的键位是**从当前键位现算**的（`playerLegend()`），改完键位立刻跟着变 —— 它和按键面板读的是同一份数据，不会出现「说明说一套、面板显示另一套」。

#### 自定义按键

右上角的**键盘图标**打开按键面板：1P / 2P 两个标签页各列 12 个钮，点某一项进入捕获态（那一格会闪），按下新键即改绑，`Esc` 取消。单机双人和联机都吃这一套。底部两个按钮：**重载卡带**（见下）和**恢复默认**（两组一起回默认）。

钮名走**街机叫法**：方向箭头 + `A B C`（下排）/ `X Y Z`（上排）+ `投币` / `开始`。内部仍对应 RetroArch retropad 的 `b/a/y/x/l/r/select/start`（`A→b`、`B→a`、`C→y`、`X→x`、`Y→l`、`Z→r`、`投币→select`、`开始→start`），这样一套面板同时盖住 NES / SFC / 街机三种机种。

三条规矩：

- **两个钮不能绑同一个键，跨玩家也不行**——一律拒绝。单机双人时两人共用一块键盘，重叠就是互相抢键；联机时房主的 P2 一旦和自己的 P1 撞上，注入会连带驱动他自己的 P1（注入合成的事件由**核心启动时读的那张表**解析，同一个键会同时算给两个玩家）。默认那两套本来就不重叠，真撞上了多半是配错了。
- **`\` 和 `` ` `` 这两个键绑不了**：Nostalgist 的具名键表里它们对应的是空串（我们直接剔掉了），配置层面就写不出去。与其给你一个「按了没反应」的键，不如当场拒绝。
- 键位存在 `localStorage`（`nesload:keybindings`），任何一处不合法就**整份**退回默认值。

**改完要重载卡带才生效**（房主和单机都是）——RetroArch 的键盘映射是启动时一次性读进核心的，运行时没有重载接口。面板底部的**重载卡带**按钮就是干这个的：它会先存一份当前快照、重新启动核心、再把快照读回去，所以改键位不会把游戏打回标题画面。（手动「弹出」再插一遍是等效的，只是会从头开始。）

唯一的例外是**加入者**：他本机没有模拟器，按键只是转成钮名发给房主，所以改完立刻生效，不用重载。

> 加入者这个例外有个前提：**本机没在跑自己的卡带**。加入者在房主出画面之前可以先自己插一盘玩，那时跑的是本机模拟器、按玩家 1 的键位读键盘，改完一样要重载卡带。面板底部的提示会按这个状态分开说，重载按钮在没插卡带时是灰的。

实现上只有一个着力点：本地读键（RetroArch 查 `input_playerN_*`）和联机注入（`pressDown` → 查同一张表 → 合成键盘事件）**共用同一份配置**，所以改一张表两条路一起变。换算**以 RetroArch 的键名为准**（见 `input/input_keymaps.c`）：`KeyX` → 单字符小写、`DigitN` → `numN`（字母上方那排数字）、`NumpadN` → `keypadN`（小键盘）、其余查具名表。**不能往返的键一律不接受**。

> 这里有个坑值得单独说：Nostalgist 的 `getKeyboardCode`（配置键名 → DOM code，只用于联机注入）把 `num*` / `keypad*` 两组**写反了** —— 它认为 `num*` 是小键盘，正好和 RetroArch 相反。早先这张表是照着它写的，结果小键盘按了没反应、反倒是数字行在动。
>
> 所以注入那条路**不再用它的解码器**：核心启动时会把它换成我们自己的（`lib/emulator.ts` 的 `overrideInjectionKeyMap`，注入要的 DOM code 本来就是我们写进配置的那份键位）。**在那之前，小键盘键在联机里是死的** —— `keypad4` 会被解成 `Digit4`，和绑定对不上，表现正好是「方向键能动、面键全不动」（方向键走具名表，没被解错）。本地双人从头到尾不受影响，RetroArch 直读键盘。

### 暂停 / 存档 / 读档

暂停、重载（重启核心）、存档、读档都走**机身前面板上那排按钮**，没有键盘快捷键。

> 早先有 `P` 暂停 · `R` 重置 · `F5` 存档 · `F8` 读档 四个全局快捷键，2026-10-10 全部撤掉：它们都是「看不见的操作」，按错的代价却不小——`P` 一按画面就冻在最后一帧，看着和卡死没区别；`F5` 会直接把存档槽顶掉一份。这四件事在面板上一人一颗钮，看得见、点得到，不需要键盘那条路。
>
> 暂停时屏幕中间会打出 `PAUSED` 和 `PRESS RESUME ON THE PANEL`——画面冻住时那条提示是唯一能说清「发生了什么、去哪儿按回来」的地方。

## 支持的格式

- **NES**：`.nes` `.fds` `.unf` `.unif`
- **SNES**：`.sfc` `.smc` `.swc` `.fig` `.bs`
- **街机**：`.zip`（romset）。**`.7z` / `.rar` 不支持**——FBNeo 只吃 zip，这两种连机种都认不出来（按键说明弹窗里会明说是格式问题）。

机种识别会优先读取文件头（iNES / UNIF / FDS 的 magic number、SNES 校验和的启发式判断，以及 zip 的本地文件头 `PK\x03\x04`），只有识别不出来时才回退到扩展名。因此即使 ROM 被改过名，也能挂载到正确的核心。

街机挂的是 **FBNeo** 核心——一套 romset 覆盖 CPS1 / CPS2 / Neo Geo 和大量 8-16 位基板，是「一个核心管一大片」的那个。核心文件随仓库放在 `public/cores/`（`fbneo_libretro.js` + `.wasm`，约 46 MB），运行时从本站加载。四点必须提前知道：

- **romset 是版本锁死的**。zip 里的文件必须和 FBNeo 期望的版本对得上，对不上就直接不加载——表现和「格式不支持」一样是静默的（屏幕继续出雪花）。
- **FBNeo 靠 zip 的「文件名」认驱动名**（去掉扩展名那一截，`kof98.zip` → `kof98`）。romset 被改过名——中文名、下载站加的 `(1)` 后缀——一样静默失败。启动时 `console` 会打出这次用的名字，名字里含非 ASCII 字符时还会额外提醒一句。
- **Neo Geo 需要 BIOS**（`neogeo.zip`）：把这个文件**直接拖进页面**就装上了——和拖卡带是同一个动作，之后每次启动街机自动带上。识别**只看文件名**（`neogeo` 开头即可，`neogeo-bios.zip` 也算），所以别把它改成跟 neogeo 无关的名字。CPS1 / CPS2 那类（三国志、街霸、名将）**不需要** BIOS。仓库里不放 BIOS，得你自己准备。
- **载入失败在界面上是静默的**（屏幕里不放任何文案，见下文），所以排查要看浏览器 `console` —— 那里有文件名、机种、核心名和 romset 名。不过按键说明弹窗里还会兜一句最可能的原因：压缩格式不对。**缺 `neogeo.zip` 和 romset 版本对不上这两种情况 2026-10-09 起界面上不再有任何提示**（原先那两行按用户要求删掉了），只能看 `console`。

## 存档

每个游戏有 **5 个存档槽**。点面板的「存档」就写一份新快照；写满 5 份之后再存，**顶掉最早的那一份**——所以不需要手动清理，也不需要给槽位起名字，**时间是唯一的区分方式**（每次存档都开一个新槽，不做同名覆盖）。

点面板的「读档」会浮出一张列表，按时间从新到旧列出这个游戏的全部存档，点哪一条就载入哪一条。列表刻意**不放进屏幕里**——「屏幕里不放任何文案」是这个项目的一条硬规矩，所以它是一块浮在房间上的面板，点背板或按 `Esc` 关掉。

快照存进 IndexedDB（和卡带库同一个数据库、不同的 store），存的是 Blob 而不是 base64。早期版本把存档按 `nesload:state:<ROM 文件名>` 存在 localStorage 里、每个游戏只有一份；升级后第一次读某个游戏的存档列表时，旧存档会自动搬进槽位。

「导出」按钮仍然可以直接下载 `.state` 文件，「导入」可以把它读回来——这条路和槽位相互独立。

## 联机

右上角的链条按钮打开联机面板。

- **创建房间** —— 生成一个 4 位房间码（字符集是 Crockford Base32 去掉 `I` `L` `O` `U`，免得和 `1` `0` 看混）。
- **加入房间** —— 把对方念给你的 4 位码输进去。输入时 `O`→`0`、`I`/`L`→`1` 会自动纠正。
- **离开房间** —— 房主离开后对方退回「等待中」，房间仍然开着，可以再等一个人。

**没有房间列表。** 列出「谁在开房」需要一台所有人都在线的注册服务器——那正是这个方案要避开的东西。房间码只能带外传递：念给对方、或用别的方式发过去。

### 怎么一起玩

**房主出画面，加入者只负责看和按。** 房主本机跑模拟器，把屏幕的画面和声音推给加入者；加入者不跑模拟器，也不需要有那盘卡带。

1. 一方「创建房间」，把 4 位码给对方；对方输码「加入」。两边都显示「已连接」。
2. **房主插上卡带**（拖进屏幕，或从右上角游戏库弹窗里点开）。插上的一瞬间画面就开始推了——加入者的屏幕会从雪花变成同一个画面，机身的插卡舱里躺着的也是房主那盘。
3. 选一款**双人**游戏。房主用 1P 键位，加入者用 2P 键位——加入者的按键会发给房主，由房主注入成 2P。
4. 按键前先**点一下页面空白处**：焦点停在面板按钮上时，模拟器不会读键盘（见下）。

加入者那边面板上会先写「已连接，等房主插上卡带」，房主插上之后变成「房主正在玩：XXX」。

### 它是怎么连上的

信令走 **Trystero** 的公共 MQTT broker（默认 `broker.emqx.io`）。它只在中途转发几条建连消息；建连之后，**按键和画面都走 WebRTC 点对点直连**，不再经过它。

所以严格说是「没有**我们自己的**服务器」，而不是「完全没有服务器」。局域网内直连延迟通常在个位数毫秒。代价是双方都要能访问那个公共 broker——完全断网的内网里连不上。

### 直连失败时：TURN

Trystero 默认只带 STUN（`stun1-3.l.google.com` + `stun.cloudflare.com`），**没有 TURN**。STUN 只负责告诉对方「我的公网地址长这样」，真正打洞还得两端自己能通。下面这些情况就会失败：

- 路由器开了 **AP 隔离 / 客户端隔离**（同一个 WiFi，但设备之间根本不能互访）
- 第三方安全软件（360 / 火绒 / 电脑管家）拦入站 UDP —— 它和 Windows 自带防火墙是两回事，系统防火墙默认不拦出站、对 UDP 还有状态跟踪，一般不是主因
- 企业或校园网只放行 TCP 443
- 跨网络的对称 NAT / 运营商 CGNAT

失败时面板会提示「双方都连上了中继，但建不起直连」，控制台里另有 Trystero 的英文原文（`[netplay] join error: …`）。想确认卡在哪一段，开 `chrome://webrtc-internals` 看 `ICE candidate pairs`：全是 `failed` 就是网络层被挡了，有一条 `succeeded` 就说明网络是通的、问题在别处。

**要跨过这一层只能配一台 TURN 服务器**（自建 coturn，或用付费服务），由它把流量中继过去。填三个环境变量即可，不填就还是原来的 STUN-only 路径、行为一点不变：

> 联机面板顶上有个「**局域网 / 公网**」选择器。**局域网** = 只带 STUN（也就是原来的行为）；**公网** = 额外带上 TURN 兜底，但**仍然先试直连**，直连能通就不会走中继（ICE 的候选优先级是 host → srflx → relay，这是白送的，不用额外写逻辑）。构建期没配 `NEXT_PUBLIC_TURN_URL` 时「公网」这一档会显示「正在开发中」—— 把那三个变量配好、重新构建之后它会自动解锁。

```bash
NEXT_PUBLIC_TURN_URL=turn:turn.example.com:3478   # 多个地址用逗号分隔
NEXT_PUBLIC_TURN_USERNAME=user                    # 可选
NEXT_PUBLIC_TURN_CREDENTIAL=pass                  # 可选
```

这些值在**构建期**被内联进客户端代码（`NEXT_PUBLIC_` 前缀的固有行为），改了要重新构建。另外 TURN 是**中继**，走它会明显增加延迟——能用直连就别配。

#### 自己搭一台 coturn

用 Docker，`network_mode: host` 最省事（TURN 需要真实 IP 和一大段 UDP 端口）：

```yaml
services:
  coturn:
    image: coturn/coturn:latest
    restart: unless-stopped
    network_mode: host
    command:
      - -n
      - --log-file=stdout
      - --listening-port=3478
      - --min-port=49160
      - --max-port=49200
      - --realm=turn.example.com
      - --lt-cred-mech
      - --user=nesload:<一串长随机密码>
      - --fingerprint
      - --no-cli
      - --no-tlsv1
      - --no-tlsv1_1
      # 云主机在 NAT 后面时必写，格式是 <公网IP>/<内网IP>。
      # 不写的话候选地址会填内网 IP，外面根本连不上。
      - --external-ip=<公网IP>/<内网IP>
```

不想用 Docker 就 `apt install coturn`，同样这些参数写进 `/etc/turnserver.conf`，并在 `/etc/default/coturn` 里打开 `TURNSERVER_ENABLED=1`。

**要放行的端口**（云厂商安全组和系统防火墙**两处都要开**）：

| 端口 | 协议 | 用途 |
|------|------|------|
| `3478` | UDP + TCP | TURN 主端口 |
| `49160-49200` | UDP | relay 端口段，必须和 `--min-port` / `--max-port` 一致 |

**凭据用 `lt-cred-mech` + `--user=` 这种静态的。** 另一种 `use-auth-secret` 模式的用户名是「过期时间戳」、密码是 HMAC-SHA1 算出来的，会过期——写不进构建期就固定的环境变量，别用。

验证：浏览器开 [Trickle ICE 测试页](https://webrtc.github.io/samples/src/content/peerconnection/trickle-ice/)，填上 `turn:你的IP:3478` 和用户名密码，看到 **`typ relay`** 的候选就说明服务器通了。

> ⚠️ **`NEXT_PUBLIC_*` 会被打进客户端产物。** TURN 凭据打开 DevTools 就能看到，别人可以拿你的服务器当免费中继白嫖带宽。自用场景可以接受，但密码务必长随机，并给 coturn 限速（`--max-bps`、`--user-quota`、`--total-quota`）。

### 画面和声音是怎么过去的

- **画面**：`canvas.captureStream(60)` 把模拟器画布直接抓成一条 `MediaStream`。
- **声音**：RetroArch 的 WASM 构建把音频交给 Emscripten 的 WebAudio，而 Nostalgist 没有暴露任何音频节点（整个包里零个 `AudioContext` 引用）。所以我们在 `AudioNode.prototype.connect` 上打了个补丁——凡是**往 `ctx.destination` 连**的节点，顺手也连一份到我们自己建的 `MediaStreamAudioDestinationNode`。只是**多接一路**，本机的声音完全不受影响。
- 两条轨道合成一条流交给 Trystero 的 `addStream` 推过去。对方连上之前调用不会丢——`onPeerJoin` 里会补发一次。

推的是**同一帧画面**，所以加入者看到的和房主天然同步，不存在「各跑各的、越跑越偏」的问题。

### 键位与角色

创建者是 **1P**（默认 `W` `A` `S` `D` + `J` `K` `L` / `U` `I` `O` + `B` / `Enter`），加入者是 **2P**（默认方向键 + 小键盘 `1` `2` `4` `5` `7` `8` + `Del` / 小键盘 `0`）。两边都能用右上角的按键面板改（见「键位 → 自定义按键」）。

转发是**单向**的：加入者按的键发给房主、由房主注入成 2P；房主自己的键由 RetroArch 直接读，加入者是从画面里看到这一下动作的。

> **两边各配各的。** 加入者改的是**自己**的 2P 键位，跟房主怎么配无关——加入者只把「哪个钮」发过去，房主那边按自己的表合成一个按键事件喂给核心。也正因如此，加入者改完立刻生效，不用重载卡带（前提是他本机没在跑自己的卡带，见「键位 → 自定义按键」）。

> **ROM 不传输。** 加入者拿到的是渲染后的画面，不是卡带文件——这个项目不会变成 ROM 分发工具。代价是玩什么完全由房主决定，加入者换不了游戏（想自己玩就先离开房间）。

### 已知的不足

- **操作有延迟。** 加入者的按键要绕一圈（加入者 → 房主 → 模拟器 → 画面 → 加入者），局域网内大约 60~160ms。休闲游戏够用，精确跳跃类会明显偏软。
- **房主是单点。** 房主卡住、弹卡、关掉页面，加入者那边就黑了。
- **要求双人游戏。** 加入者按的是 2P 键位，而单人游戏只认 P1。
- **焦点落在按钮上时模拟器不读键盘。** Nostalgist 会跳过事件目标为 `<button>` / `<input>` / `<a>` 的按键。关掉面板时我们会主动 `blur()`，但如果你自己点了某颗按钮又立刻按键，先点一下页面空白处。
- **音频旁路没有兜底。** 如果核心的音频不是通过 `connect(ctx.destination)` 接出去的（换核心、Emscripten 换后端），加入者就会只有画面没声音。抓流时会重试 5 秒等音频节点，之后放弃。

## 多语言

界面支持中文 / 英文，右上角有语言开关。

语言解析顺序（服务端与客户端共用 `lib/i18n.ts` 里的同一套逻辑，所以首屏渲染结果和水合结果必然一致）：

1. `nesload_locale` cookie —— 用户手动切换过语言
2. `Accept-Language` 请求头 —— 即浏览器设置，`zh*` 走中文
3. 英文 —— 一条都没匹配上时的兜底

> 语言是在根布局里用 `cookies()` / `headers()` 读的，所以这个路由是动态渲染 —— 换来的是首屏文案直接就是对的，不会先渲染英文再翻成中文。代价是不能再用 `output: 'export'` 做纯静态托管。

界面上所有 `font-pixel` 的文案（`PWR` / `VOL` / `BETA` / `DESKTOP ONLY` / `EXIT FULLSCREEN`，屏幕里的 `DRAG & DROP A ROM` / `RELEASE TO LOAD` / `WAITING FOR HOST` / `PAUSED` / `PRESS RESUME ON THE PANEL`，以及 NES·SFC·ARC 机种标签、存档计数、房间码、进度条百分数这些纯 ASCII 读数）刻意保持英文：Press Start 2P 没有中日韩字形，塞中文会掉进等宽字体兜底，和像素风不搭。

**按键说明**弹窗里那两行键位（`playerLegend()` 现算）是这条规矩的例外：它是给人读懂的说明，所以走系统字体、做了中英两版。原先那版是 `font-pixel` 的英文，只列键名不说对应关系（`1P ARROWS / Z X / A S / Q E / SHIFT / ENTER`），等于没说明白。压缩格式那条提示也挂在同一个弹窗里（见「支持的格式」）。

屏幕里**不放任何说明文案**，能上屏幕的只有状态提示（怎么开始玩 / `RELEASE TO LOAD` / `WAITING FOR HOST` / `PAUSED` / 载入进度条）：没插卡带就是一片雪花，插上就直接出画面。状态一律优先由机身上的东西表达——`PWR` 灯的颜色（暂停时会变成 accent 色）、面板按钮的可用状态。因此载入失败、存档结果这类一次性反馈没有对应的界面元素，也没有 OSD。进度条那个百分数是**读数**、不是文案，和 `EXIT FULLSCREEN` 同性质。

## 已知限制

- **NES / SFC 首次运行需要联网**：核心由 Nostalgist 从 CDN 拉，首次启动要等十几秒（实测约 18 秒）。**街机的核心是本站文件**（`public/cores/`），不依赖网络。插卡带的这段时间**屏幕里**会显示进度条：拿得到核心的 `Content-Length` 就是百分比，拿不到就是一条来回滑动的「不确定」条（核心进过 CacheStorage 之后基本就是后者）。
- 字体 Press Start 2P 通过 `<link>` 在运行时加载。这里刻意没用 `next/font`（它会在构建时下载字体，无网络环境下会让构建直接失败）；加载失败时优雅退化为等宽字体，不影响功能。
- 卡带和存档都放在 IndexedDB 里；拿不到 IndexedDB 时（隐私模式等）「历史」会空着，此时点「存档」会自动降级为下载 `.state` 文件。
- 只支持桌面端：窗口窄于 900px 时整个场景会被替换成一句提示。断点是按场景宽度撑出来的——电视机 766px 加两侧 `px-6` 约 814px。原先并排着卡带架时是 1100px，卡带架撤掉后跟着降到了 900px。
- 联机要求双方都能访问公共 MQTT broker（默认 `broker.emqx.io`），**完全断网的内网用不了**。没有房间列表——房间码只能口头或手动传递。玩什么由房主决定，加入者只收画面、不能自己换游戏。详见上面的「联机」一节。
- 任何 `.zip` 都被当作街机 romset。把一盘 NES / SNES ROM 压成 zip 拖进来**不支持**——它会被交给 FBNeo，然后静默失败。
