# nesLoad

在浏览器里运行的复古游戏机，目前有**十四个机种**：NES（中文站显示 FC，即红白机）/ SFC / GB / GBC / GBA / NDS / 世嘉 MD / Game Gear / Master System / 世嘉 32X / WonderSwan / Neo Geo Pocket / 索尼 PlayStation（PS1）/ 街机。界面是一台极简像素风的电视机：把 ROM 文件拖到机身上（或点机身下沿的插卡口），卡带就会插进去开始运行。

模拟内核基于 [Nostalgist](https://nostalgist.js.org/)（封装 RetroArch 的 WASM 构建）。**十四个机种的核心全部随仓库放在 `public/cores/`，运行时从本站加载、不依赖任何 CDN**（2026-10-19 起 NES / SFC 也从 CDN 搬了过来：jsdelivr 在国内经常连不上或被限速，拉不动就表现成「拖进去毫无反应」）。**仓库内不包含任何 ROM**——`public/cores/` 里是开源的 WASM 核心构建，不是 ROM。

## 开始

部署到 Cloudflare Workers 的构建命令、R2 页面缓存绑定和免费版限制，见 [部署说明](docs/cloudflare-deployment.md)。

```bash

pnpm dev
```

打开 http://localhost:3000。

## 界面与操作

界面只有两个东西：**电视机**和机身下沿的**插卡口**。载入游戏有三种方式：

1. 把 `.nes` / `.sfc` / `.gba` / 街机 `.zip` / PS1 的 `.pbp` `.iso`（或装着 `.cue` + `.bin` 的 `.zip` / `.7z`）文件直接拖到电视机上（街机的 `neogeo.zip` **站点已经自带一份**，不用你操心；PS1 的 BIOS 站点**不带**，但核心找不到会回落 HLE、游戏照跑，想要更好兼容性就自己拖一份 SCPH1001.BIN 进来；两份都走这条路，见「支持的格式」）；
2. 点机身下沿的插卡口，在文件选择框里挑；
3. 点右上角的**游戏库**图标，从弹窗里挑：在线库直接下载，「历史」里是从游戏库点开过的那批（点一下重新下一遍）。

卡带插进去以后只露出**侧面那一条**——就是真实卡带插进机器后你能看到的那一面，名字沿长边走。点前面板的「弹出」把它取出来。

前面板上还有一组音量档位（`VOL`）：六格代表六档，点第 n 格就是第 n 档，两端的 `−` / `+` 微调，`−` 按到底即静音（六格全暗）。档位记在 `EmulatorController` 里，所以还没插卡带时调也有效，插上时作为初值生效。

相邻两档差 **6 dB**，1 档到 6 档一共 30 dB。间距刻意取这么大：原先的 4 dB 会被当成「按了没反应」。最大档也**不是**原音量，而是比 RetroArch 的默认满音量（0 dB）低 6 dB —— 0 dB 在浏览器里放 NES 游戏明显偏吵。运行时音量靠 `VOLUME_UP` / `VOLUME_DOWN` 一条条补（RetroArch 每条只走 0.5 dB，而且没有 SET_VOLUME），所以跨一档要发 12 条命令。

面板右侧那排是存档相关的按钮：**存档**写一份新快照，**读档**浮出存档列表，**导入 / 导出**走 `.state` 文件，**弹出**把卡带取出来。

### 游戏库 / 历史

右上角那个**游戏库**图标点开是个全屏弹窗，里面两个 tab：

- **游戏库** —— 后台上传到 R2 + D1 的游戏，网格排封面，点一个把 ROM 拉回来直接插进卡槽。ROM 走本站代理（`/api/games/[id]/rom`），下载进度叠在封面底部那一条上。列表是**服务端分页**的：一行最多 5 个（屏幕变窄依次降到 4 个、最少 3 个），**一页 15 条**，底部一条翻页；机种筛选和搜索都跟着分页一起下发到 `/api/games`，换条件就回到第 1 页。搜索是**提交式**的（点「搜索」或回车才发请求）—— 一次查询是两次 D1 往返（COUNT + SELECT），不边打字边请求。

  后台上传 / 编辑时可以填一行**说明**（`games.description`，可空，2026-10-12 加的）。它不进卡片正文 —— 卡片是一行五个的小格子放不下整句中文 —— 只作**悬停提示**（鼠标停在卡片上，标题下面接一行说明）。说明**不在搜索范围内**（搜索仍只匹配游戏名 / 开发者 / 系列）。给已经在用的库补这一列要单独跑一次 `node --env-file=.env.local scripts/add-games-description.mjs`（只做 `ALTER TABLE ... ADD COLUMN`，不碰任何数据、可重复执行）。
- **历史** —— **从游戏库点开过**的那批（2026-10-12 改造）。记录里只有字符串：名字、封面地址、ROM 下载地址、文件名，**不存 ROM 本体**。按最后游玩时间倒序，**最多保留 10 条**，超出后自动淘汰最旧的一条。点一行 = 照存下来的地址**重新下一遍**（进度条在电视机屏幕上），行尾的 × 是移除。

> 自己拖进来的本地文件**不进历史**：它没有可重新下载的地址，存进去也点不动。想再玩一次就再拖一遍。

> 改版前历史存的是 ROM 的 Blob 本体（几 MB 起，只记本机拖入的那批）。`DB_VERSION` 因此从 3 升到 4，升级时**整个 `cartridges` store 删掉重建**，老记录不做搬运 —— 历史是纯便利数据，丢了不影响任何东西（游戏本体在服务端）。

> 电视机右侧那个**卡带架** 2026-10-09 撤掉了：它和「历史」是同一份数据，留两处只会分叉。架子那套「开放式立柱 + 一格一根横档」的做法连同 `CartridgeRack.tsx` 一起删了，真要找回来去 git 历史里捞。

插在机身上的那盘用 `CartridgeSprite`（标贴 + 塑料前缘两段），宽度由父容器定，插卡舱里是 359px。

### 房间里的彩蛋

屋里能点的东西一共**七处**：

| 位置 | 点一下 |
| --- | --- |
| 吊灯（灯罩 + 灯泡） | 开 / 关灯 |
| 窗户玻璃 | 换下一季（春 → 夏 → 秋 → 冬） |
| 墙上那幅**挂画**（画框） | 放大看这张画，下面摆画名和作者 |
| 地板中间的**留言本** | 开留言面板（**彩蛋** —— 正经入口是右侧那排开关里那颗） |
| 地板右下角的**纸片** | 弹出「一张纸」（唯一入口） |
| 地板最右侧的 **MP4** | 播放 / 暂停（唯一入口） |
| 地板上的**逗猫棒** | 电视机左边那摞书后面探出一个猫头（每次换品种） |

剩下的（墙 / 桌子 / 电视机 / 地板）才是**不吃事件**的装饰（`pointer-events-none` + `aria-hidden`）。
⚠️ 上面这七处**各自会吃掉自己那一小块的拖拽落点** —— 拖着 ROM 恰好从它们身上松手不会载入，别处照旧。

**墙上那幅挂画**是 2026-10-12 把原来那本日历换掉的：七幅像素画里**刷新随机抽一幅**（向日葵 / 蒙娜丽莎 / 星月夜 / 呐喊 / 戴珍珠耳环的少女 / 神奈川冲浪里），第七幅是用户自己的照片改的，说明牌上照他指定的写法写「不知从哪来的不知名画作 · 佚名」。**点画框放大看**，画面就是同一份笔画数据放大（不另画一张），下面一块米色说明牌摆画名和作者；点背板 / `×` / `Esc` 关掉。唯一的例外是**第七幅**：十几格的粗颗粒放大后认不出人，用户 2026-10-12 又提了「点开看大图时高清一点」，于是单独给它备了一张 90×96 的细粒度版本（`public/paintings/beach.png`，由那张原照片降采样 + 64 色量化，仍是硬边像素；尺寸是墙上那版 15×16 的整 6 倍），**只换大图、墙上不动** —— 字段是 `PixelPainting.detail`，留空就还是放大笔画那套。

**窗外是会动的**（2026-10-12 加）：夜里星星各自慢慢闪（周期 3.4–5.6 秒、逐颗错开相位，不会整齐划一），白天云慢慢往右飘（62 格一个周期、90 秒走完，首尾逐像素接得上）。四季各有各的月亮（春 / 夏是月牙、秋是满月、冬是一轮冷月）—— 这些本来就画在景色里，原先只是全都钉着不动；这次只让**星星和云**动起来，云**补了第二朵**（按第一朵左移 62 格，正好一个循环），其余景物照旧是静的。

**那台 MP4** 摆在**右侧桌腿的右边**，插着一副有线耳机（线随意甩在地上，从纸片和手柄底下绕过去）。播放时屏幕里滚「歌词」、底部几条电平条按 `steps()` 硬跳；暂停时屏幕中央两条竖杠。

它的横坐标**不写死**，跟着 `--desk-w` 算（`.mp4-anchor` / `.mp4-cord-anchor`，见 globals.css）—— 桌面宽会随电视机尺寸档位和窗口大小变（1080 高的窗口上：小 925 / 中 1029 / 大 1133），桌腿因此整体右移，写死坐标切档就会和桌腿叠在一起。代价是窄窗口下它在 `main` 的裁切范围之外，**要窗口够宽（小档在 1080 高的窗口上约 1020px 起，见 globals.css 那个 360）才看得见**，和右侧桌腿一样。

首选音源是 `/audio/i-miss-you.mp3`。**仓库里不带那首 mp3** —— 它是有版权的录音制品，要自己准备一份放进 `public/audio/`（文件名必须是 `i-miss-you.mp3`，详见该目录下的 README）。**放不出来会自动退到现场摇的 8-bit 小段**（`lib/chiptune.ts`，运行时手搓一段 1.3–3.8 秒的 WAV）—— 所以点下去不会哑。那一小段**每点一次都摇一段新的**（主音 / 调式 / 速度 / 音色 / 旋律全随机），而且**放一遍就停**（真歌是循环的）；兜底也只退一次，刷新页面才会重新先试那个文件。

> 播放状态是**全屋唯一留在 React 里**的一份（不进 `<html data-*>`、不落盘）：刷新页面本来就该停。吊灯 / 简洁模式 / 电视机尺寸那几件之所以挂 DOM 属性，是因为它们要在首屏之前就生效，这里没有这个问题。

### 主题与全屏

右侧竖着一排开关（上下居中贴右边，不压机身）：**夜晚 / 白天**、**游戏库**、**全屏**、**简洁模式**、**电视机大小**、**联机**、**自定义按键**、**按键说明**。

- **主题是一颗钮，点一下来回切**（2026-10-12 改版，原来是两格常驻的分段控件）：露的是**切过去之后**的图标（当前夜晚就露太阳），title 说的也是同一方向。**语言那颗钮 2026-10-13 整颗挪去了右上角那排**（见「多语言」一节）—— 语言分在路径上之后，切换的实质是导航到另一个地址，一条链接比一颗钮诚实。
- 主题由 `<html data-theme>` 驱动，首屏由内联脚本写入，不会闪一帧深色。浅色主题是把整条 `ink` 灰阶反过来映射，所以组件的颜色类一行都不用改。屏幕内部例外——显像管底永远是黑的，那里用一组固定的 `crt-*` 令牌。
- 主题钮露哪颗图标**同样由 `data-theme` 用 CSS 决定**，不走 React state——否则首帧会先按默认主题画一颗再「啪」地换过来。React 那份 theme state 只喂 `title / aria-label`。
- 全屏的是**屏幕本身**而不是整页，canvas 用 `object-fit: contain` 做等比留边。全屏后屏幕右上角会出现退出按钮。
- **简洁模式**由 `<html data-simple>` 驱动（同样由首屏内联脚本写入），点一下只留**背景墙 / 电视机 / 桌子 / 地面**，把吊灯、窗户、墙上那幅挂画、地板杂物（含留言本、纸片和那台 MP4）整体藏掉。状态记在 localStorage，刷新后还在。
- **电视机大小**由 `<html data-tv>` 驱动（首屏内联脚本写入，记在 localStorage）：点一下那颗钮，**左侧弹出「大 / 中 / 小」三档**，点哪档切哪档，当前那档高亮（高亮也是 CSS 按 `data-tv` 选的，不吃 React）。**三档不是写死的 px，而是「这间屋子塞得下的最大屏幕」的 80% / 90% / 100%**（2026-10-13 改；原来是写死的 720 / 840 / 960，用户在大屏上反馈「切到『大』占比还是很小」。占比最初继承旧档比例取 75 / 87.5，同日用户看了实际效果要求小 / 中再大点，抬成 80 / 90）——所以窗口越大三档整体越大，大档永远 = 屋子塞得下的最大那一档（27" 2K 上 **1127×845**，比旧的大档还大一截）；窗口窄 / 矮时三档一起收，顺带修掉了「窄窗口机身被切、矮窗口桌腿被切」那两个老问题。**屏幕有个下限** `--tv-screen-min`（500，2026-10-13 补）：窗口小到让某一档掉到它以下时，那一档就停在下限、不再跟着缩（屋子会被裁掉一点）——下限是**机身自己**给的，前面板那一排固定尺寸的控件要 ~520px，机身窄于它就把机身撑宽，屏幕在机身里又左对齐，右边就空出一条（用户报的「小档游戏区域没填满电视机、右侧大片空白」；窗口越矮越明显，机身会缩成「长条形」）。所以机身宽度也钉死在 `w-[var(--tv-w)]` 上，面板那排钮改成 `minmax(0,52px)` 可以被压（最窄 ~37px）。1080 高的窗口上量出来是 **731 / 822 / 913**。三档只动屏幕尺寸、机身 / 底座 / 桌面的宽度和吊灯线长度，**机身里那些固定部件（顶沿、前面板、像素描边）刻意不跟着放大**——像素描边经不起非整数缩放。窗户和挂画锚在机身两个上角、桌子锚在机身下沿，所以换档时它们的相对位置不变；桌面固定比机身左右各宽 140px，桌上那几件小物就摆在那两条露出来的窄带里，大档也不会被机身挡掉。**机身下方必须留出「桌子总高 68（桌面 28 + 腿 40）+ 墙地交界线以下那摊地板杂物最深的一件 52」**（`--tv-below-body` = 124；2026-10-13 用户报「大档下面地板的东西很大部分被遮挡」之后补的，同日用户又要求「桌腿矮点换面积」：腿 70 → 40，这份 154 → 124，地板杂物一px没让）。**窗口矮于 1080 时优先吃的是「对称余量」而不是屏幕**（`--tv-below-breathing`，2026-10-13 补）：房间竖向居中，原来公式里直接减了两份下方预留（一份给下方桌子杂物，一份是居中的对称余量）；现在第二份改成自适应——1080 高时原样满格，窗口往下缩先吃它，吃光才轮到电视跟着缩。代价：矮窗口 + 大档时那份余量吃光后地板杂物会被下沿裁掉（「地板让位给电视」是注释里写明的取舍）。**换档和拉窗口都不用重插卡带**——核心用 ResizeObserver 盯着 canvas，尺寸一变自己重设后备存储。

### 键位

默认值（**可以改**，见下）：

**1P**：`W` / `A` / `S` / `D` 移动，`J` = A，`K` = B，`L` = C，`U` = X，`I` = Y，`O` = Z，`B` = 投币，`Enter` = 开始

**2P**：方向键移动，小键盘 `1` `2` `4` `5` `7` `8` = A B C X Y Z（三行各取左边两个，凑成一块 2×3），`Del` = 投币，小键盘 `0` = 开始

**上面那套是「通用」默认。** 有两台机器各有自己的一套（`defaultBindingsFor`）：

- **PS1**（2026-10-16 加）：`W`/`A`/`S`/`D` 移动，`I` = △，`J` = □，`K` = ×，`L` = ○，`U` = L1，`O` = R1，`Q` = L2，`E` = R2，`B` = SELECT，`Enter` = START。`IJKL` 在键盘上正好是个小十字（`I` 正在 `K` 正上方），和手柄的 △□×○ 菱形对得上 —— 语义上也是 △=上 / □=左 / ×=下 / ○=右，和十字键同构。⚠️ 通用那套套到 PS1 上是**歪的**（△ 会落在 `J` 正上方），所以单开了一套。
- **NDS**（2026-10-15 加）：方向键移动，`Z`/`X` = A/B，`A`/`S` = X/Y，`Q`/`E` = L/R，`R`/`W` = L2/R2，`Shift` = SELECT，`Enter` = START（左手管四颗面键和两排肩键，右手整只交给方向键）。

> 上面那两套按键刻意不重叠，避免双人同屏时互相抢键。机种专属那几套的 P2 也照这条规矩（PS1 直接沿用通用 P2）。
>
> ⚠️ **改键位是全局的**：本地那份（`nesload:keybindings`）**全机种共用一份**，所以在 PS1 上改过一个键之后，再去玩 NES 用的也是那份。只有「一个键都没动过」的人才会按机种拿到上面那套专属默认（判据是 `loadBindings()` 的 `LEGACY_DEFAULTS`）。
>
> 右侧那排开关里的**按键说明**（问号那个）点开是个弹窗，里面的键位是**从当前键位现算**的（`playerLegend()`），改完键位立刻跟着变 —— 它和按键面板读的是同一份数据，不会出现「说明说一套、面板显示另一套」。

#### 自定义按键

右上角的**键盘图标**打开按键面板：1P / 2P 两个标签页各列 12 个钮（**NDS / PS1 是 14 个** —— 它们多一排 `L2` / `R2`），点某一项进入捕获态（那一格会闪），按下新键即改绑，`Esc` 取消。单机双人和联机都吃这一套。底部两个按钮：**重载卡带**（见下）和**恢复默认**（两组一起回默认）。

钮名默认走**街机叫法**：方向箭头 + `A B C`（下排）/ `X Y Z`（上排）+ `投币` / `开始`。内部仍对应 RetroArch retropad 的 `b/a/y/x/l/r/select/start`（`A→b`、`B→a`、`C→y`、`X→x`、`Y→l`、`Z→r`、`投币→select`、`开始→start`）—— 一套面板就盖住 NES / SFC / GBA / 世嘉那几台 / 街机。

**丝印和街机那套不一样的机种要单独登记**（`lib/keybindings.ts` 的 `CONSOLE_BUTTONS` + `CONSOLE_BUTTON_LABELS`，两张都是 `Partial`，漏了不报错、只是退回街机叫法）：

| 机种 | 面键 | 肩键 | 开始 / 投币 |
| --- | --- | --- | --- |
| NDS | `A` / `B` / `X` / `Y` | `L` / `R` / `L2` / `R2` | `START` / `SELECT` |
| PS1 | `△` / `○` / `×` / `□` | `L1` / `R1` / `L2` / `R2` | `START` / `SELECT` |

⚠️ PS1 那四颗面键**不是按丝印顺序对齐的**，而是照 libretro 对 PS1 的标准映射：retropad `B→×`、`A→○`、`Y→□`、`X→△`（`pcsx_rearmed` 也是这一套）。所以面板上「×」落在 `b`、「○」落在 `a`、「□」落在 `y`、「△」落在 `x` —— 看着像打乱，其实是这套机器的标准。

⚠️ **那四颗符号是「画」出来的，不是文字**（`components/PadGlyph.tsx`）：`×`(U+00D7) 是 Latin-1 的乘号、多数西文字体按 x-height 画得很小，而 `○`(U+25CB) / `□`(U+25A1) / `△`(U+25B3) 属几何图形区、只能掉到 CJK 兜底字体里当**全角**字画 —— 同一个 `font-size` 下必然一大三小（2026-10-16 用户报「圈叉三角正方形大小都不是统一的」）。所以这四个（含按键说明页脚那一行、机身面键、撞键提示）一律走 `PadGlyph` 换成**定尺矢量图形**，跟着 `font-size` 缩放；**别的钮名（`A` / `L1` / `SELECT` …）原样还是文字**。想调描边粗细只改 `PadGlyph.tsx` 里那一个 `strokeWidth`。

> ⚠️ **PS1 还有 `L3` / `R3`（摇杆按下去）和类比摇杆，本站没有**：键位模型只有 14 个钮（`ButtonName`），画不出也绑不了这两颗；摇杆更是完全没建模（键盘 / 手柄的左摇杆推过阈值只当**方向键**用，见 `lib/gamepad.ts` 的 `STICK_THRESHOLD`）。绝大多数 PS1 游戏用十字键就能玩，但**必须用摇杆的那几款（《捉猴啦》这类）玩不了** —— 这是已知缺口，不是 bug。

三条规矩：

- **两个钮不能绑同一个键，跨玩家也不行**——一律拒绝。单机双人时两人共用一块键盘，重叠就是互相抢键；联机时房主的 P2 一旦和自己的 P1 撞上，注入会连带驱动他自己的 P1（注入合成的事件由**核心启动时读的那张表**解析，同一个键会同时算给两个玩家）。默认那两套本来就不重叠，真撞上了多半是配错了。
- **`\` 和 `` ` `` 这两个键绑不了**：Nostalgist 的具名键表里它们对应的是空串（我们直接剔掉了），配置层面就写不出去。与其给你一个「按了没反应」的键，不如当场拒绝。
- 键位存在 `localStorage`（`nesload:keybindings`），任何一处不合法就**整份**退回默认值。

**改完要重载卡带才生效**（房主和单机都是）——RetroArch 的键盘映射是启动时一次性读进核心的，运行时没有重载接口。面板底部的**重载卡带**按钮就是干这个的：它会先存一份当前快照、重新启动核心、再把快照读回去，所以改键位不会把游戏打回标题画面。（手动「弹出」再插一遍是等效的，只是会从头开始。）

唯一的例外是**加入者**：他本机没有模拟器，按键只是转成钮名发给房主，所以改完立刻生效，不用重载。

> 加入者这个例外有个前提：**本机没在跑自己的卡带**。加入者在房主出画面之前可以先自己插一盘玩，那时跑的是本机模拟器、按玩家 1 的键位读键盘，改完一样要重载卡带。面板底部的提示会按这个状态分开说，重载按钮在没插卡带时是灰的。

实现上只有一个着力点：本地读键（RetroArch 查 `input_playerN_*`）和联机注入（`pressDown` → 查同一张表 → 合成键盘事件）**共用同一份配置**，所以改一张表两条路一起变。换算**以 RetroArch 的键名为准**（见 `input/input_keymaps.c`）：`KeyX` → 单字符小写、`DigitN` → `numN`（字母上方那排数字）、`NumpadN` → `keypadN`（小键盘）、其余查具名表。**不能往返的键一律不接受**。

> 这里有个坑值得单独说：Nostalgist 的 `getKeyboardCode`（配置键名 → DOM code，只用于联机注入）把 `num*` / `keypad*` 两组**写反了** —— 它认为 `num*` 是小键盘，正好和 RetroArch 相反。早先这张表是照着它写的，结果小键盘按了没反应、反倒是数字行在动。
>
> 所以注入那条路**不再用它的解码器**：核心启动时会把它换成我们自己的（`lib/emulator.ts` 的 `overrideInjectionKeyMap`，注入要的 DOM code 本来就是我们写进配置的那份键位）。**在那之前，小键盘键在联机里是死的** —— `keypad4` 会被解成 `Digit4`，和绑定对不上，表现正好是「方向键能动、面键全不动」（方向键走具名表，没被解错）。本地双人从头到尾不受影响，RetroArch 直读键盘。

### 暂停 / 存档 / 读档

暂停、重载（重启核心）、存档、读档都走**机身前面板上那排按钮**，没有键盘快捷键。

> 早先有 `P` 暂停 · `R` 重置 · `F5` 存档 · `F8` 读档 四个全局快捷键，2026-10-10 全部撤掉：它们都是「看不见的操作」，按错的代价却不小——`P` 一按画面就冻在最后一帧，看着和卡死没区别；`F5` 会直接把存档槽顶掉一份。这四件事在面板上一人一颗钮，看得见、点得到，不需要键盘那条路。
>
> 暂停时屏幕中间会打出 `PAUSED` 和 `PRESS RESUME ON THE PANEL`——画面冻住时那条提示是唯一能说清「发生了什么、去哪儿按回来」的地方。

- `/play` 的外壳是 `GamesShell`，为此给它加了两个可选 prop：`showHeader`（默认 `true`，`/play` 传 `false` —— 名字与资料在右列顶上，顶上再来个 `<h1>` 就重复了；h1 由 `PlayScene` 出一颗 sr-only 的）和 `fill`（默认 `false`，`/play` 传 `true` —— 内容 `flex-1` 吃满剩余高度，页脚因此压在视口最底）。**两个都只有 `/play` 在用**，别顺手给别的页打开。

**登录页**（`app/[locale]/login/page.tsx` + `components/LoginPanel.tsx`）：

- **背景是 canvas 画的像素装饰**（`components/LoginBackdrop.tsx`，2026-10-13 加）：三个**通用**像素小人（NES / SFC / 街机三色）在背景里慢慢飘 + 琥珀微光 + 一片闪烁像素。整层**透明**、`fixed z-0`，底色由 `main` 的 `wall` 类出（2026-10-14 起前台统一用房间背景墙同款，深浅主题自动跟着走，canvas 里的颜色也按 `data-theme` 重读）；**正文列的可读性由 canvas 自己兜** —— 小人 / 亮点飘进正文列那一竖条会淡出（`CENTER_FADE`），原来的 `.login-scrim` 遮罩已撤（平色和墙对不上）。

- **注册账号 = 邮箱**（2026-10-14 起）：注册走 `lib/email.ts` 的校验（格式 / 别名 / 临时域，**前后端共用同一份**，前端 `AuthForm` 先挡一道、服务端 `/api/user/register` 兜底）。挡的是：`+` 别名、Gmail 加点别名、临时 / 匿名转发邮箱域名（`DISPOSABLE_DOMAINS`，**会过时**，见文件内注释）。存库前 **trim + 小写**——`app_users.username` 列现在存的是邮箱。⚠️ **登录完全不校验邮箱**（用户明确要求）：老账号的用户名可能不是邮箱，登录按字符串原样查库。

**人机验证（Cloudflare Turnstile，2026-10-13 加）** —— 挂在登录 / 注册表单上（屋里那个账号浮层和 `/login` 是同一张表单，所以两处一起有）：

- 前端挂件 `components/TurnstileWidget.tsx`（**显式渲染**，`?render=explicit`），挂在 `AuthForm` 里口令下面；服务端校验 `lib/server/turnstile.ts`，接在 `POST /api/user/login` 与 `POST /api/user/register` **最前面**（字段校验 / 凭据校验之前）。

- ⚠️ **后台账号（`/api/admin/login`）刻意没加**：只有一个入口、一个管理员，加了只会先挡住自己。


### 游戏列表 / 详情 / 下载（公开页面）

2026-10-12 加的三个**真路由**，用户的原话是「增加一个游戏列表功能，放在右上角的政策旁边……每个页面的标题的说明都要写好，sitemap 都要加上」。它们和法务两页同一类：要能被搜索引擎收录、能被直接分享，所以是页面而不是房间里的浮层。

| 路由 | 是什么 |
| --- | --- |
| `/games` | 全部游戏，网格排封面，**一页 15 条**（一行 5 个 × 3 行），`/games/page/N` 翻页（真路由，爬虫顺得下去）。带搜索框（落到 `/games/search?q=<关键词>`）。副标题里的「共 N 款 / N 个结果」是现读的。数据带 **30 天缓存**（见下）。 |
| `/games/[id]` | 单款游戏的资料页：封面、标题、机种 / 年份 / 开发者 / 系列 / 语言、说明，加**四颗**主按钮（2026-10-14 加的「联机游戏」见下）。带 `VideoGame` + `BreadcrumbList` 结构化数据。 |
| `/games/[id]/download` | 下载页：点「开始下载」**等 6 秒**才真的开始下（用户要求）。**只有这一颗按钮**，没有别的下载入口。 |

- 详情页动作区：第一层四颗实体钮 —— **开始游戏** → `/room?id=<id>`（回房间，唯一带强调色）、**联机游戏** → `/play?id=<id>`（2026-10-14 加，简洁开局页，见上）、**收藏**、**下载 ROM** → 下载页。第二层两枚无描边「图标 + 文字」链接：**分享游戏**（把这一页的地址复制进剪贴板，`components/ShareGameButton.tsx`）、**反馈问题**。除分享与反馈之外全是 `<Link>` —— 它们去的是真地址，得能被复制、被新标签打开、被爬虫顺着走。
- 📌 **列表页有缓存**：`/games` 的取数是 `unstable_cache` 包过的（`lib/server/sb-games.ts` 的 `listGamesPageCached`），**TTL 30 天**（2026-10-14 从 30 分钟拉到 12 小时 —— 用户为压 `rows_read` 额度拍板；2026-10-16 提到 24 小时、2026-10-20 再提到 30 天）。**「总数」另有一层独立缓存**（`countGamesCached`，键里没有 offset）：翻多少页都只数一次全表，这是这次改动的重点。⚠️ **2026-10-20 起所有接口都不吃缓存**：房间的在线库弹窗（`/api/games`）与单条接口（`/api/games/[id]`）都实时查库（在那之前它们走同一套 `unstable_cache`）；**后台列表（`/api/admin/games`）本来就走不缓存的 `listGamesPage`**。副作用：**后台上传的新游戏最多晚 30 天才出现在这一页**（弹窗与后台自己那张列表不受影响，它们实时）。
- 详情页 / 下载页的 meta description 会**把后台填的那句「说明」放在最前面**（截到 100 字），后面接一句通用的「能玩、能下载」。没填说明就只用通用那句 —— **不编造**剧情 / 发行商那类信息。
- 游戏不存在时两页都 `notFound()`，落到 `app/[locale]/games/[id]/not-found.tsx`（一页盖住两条路由），带 `noindex`。
- 版式在 `components/GamesShell.tsx`（页头 + 返回 + 页脚互链，三页共用）；下载那颗按钮在 `components/RomDownloadGate.tsx`、分享那颗在 `components/ShareGameButton.tsx`（**这两个是这套页面里仅有的客户端组件**，其余整页留在服务端渲染）。
- 单条数据走 `lib/server/games.ts` 的 **`getGame(id)`**（对外形状，不含 `rom_url`）；页面是服务端组件、直接查库，只有**房间那条深链**走 HTTP（`GET /api/games/[id]`）。
- ⚠️ **2026-10-20 起分页与机种筛选是路径段**（`/games/page/2`、`/games/console/nes`、`/games/console/nes/page/2`），不再是 `?page=` / `?console=`。原因：查询参数那一版会被 `middleware` 的 `catalogRewrite` 改写成 `/catalog/...` 影子路由，客户端软导航对不上，只能退回整页跳转（点一次分页 / tab 白闪一下）。路径段是真路由，链接用 `next/link`。推理见 `lib/catalog-route.ts` 文件头。
- ⚠️ `/games` 会把 `/page/1` / `/page/0` / `/page/abc` / `/page/02`、认不出的机种段（`/games/console/xxx`）、以及搜索里 `?q=`（空）/ `?q=%20%20`（只有空白）/ `?q=a&q=b`（重复参数）/ 前后带空格的 / 超长被截断的、**参数顺序不对**的搜索地址，统统 **307 到规范地址**：同一个列表被两份 URL 收录就是重复内容。规范拼法：浏览态 `/games[/console/<机种>][/page/N]`（第 1 页不写 `page`、没筛机种不写 console），搜索态 `/games/search?q=…&console=…&page=…`。**越界页码**（`/page/99`）另退到最后一页，退的时候**必须把关键词和机种都带上**，否则会被踢回「全部游戏」。旧地址（`/games?page=2`）仍能打开，canonical 已指新地址。
- **机种筛选**（2026-10-13 加，2026-10-20 从 `?console=` 搬进路径）：`/games/console/<nes|snes|gba|arcade>`。页面里是一排链接（当前那颗高亮 + `aria-current`，`prefetch={false}` —— 十几颗 tab 全预取等于每开一次列表页多渲染十几条路由），搜索表单会用一个 hidden input 把机种一起提交（否则在 NES 里搜一下就掉回全库）。⚠️ **它和搜索的收录策略相反**：搜索是 `noindex, follow`，而机种筛选 **照常收录**（每个都是真实分类），canonical / hreflang 都指自己那一份。

**列表页的搜索**（2026-10-12 加）：

- 搜索框是一个**真正的 GET 表单**（`<form action="/games/search" method="get">`），不是客户端 state —— 提交后浏览器自己跳到 `/games/search?q=…`。于是搜索有真地址（可分享、可收藏、爬虫走得通），**且完全不需要 JS**。这条路由是**动态**的（`force-dynamic`，按 query 渲染），所以搜完再翻页 / 换机种是软导航，不整页刷新。
- 后端直接复用 `listGamesPage` 的 `keyword`，匹配 **title / developer / series**（不区分大小写）。⚠️ 刻意**不含 `language` 和 `description`**，理由见 `lib/server/games.ts` 的 `SEARCH_CONDITION` 注释。
- ⚠️ 翻页链接**必须带上关键词**（走同一个 `gamesHref()`），否则搜完再翻页会掉回「全部游戏」。`gamesHref` 是唯一的地址构造器：有搜索词走 `/games/search?…`，没有搜索词走路径段那份。
- ⚠️ **搜索结果页是 `noindex, follow`**：站内搜索会产出无限多的 `?q=…` 组合，每条都只是列表页的一个子集，全收进去就是重复内容、还会稀释详情页的权重。`follow` 必须留着，爬虫仍要顺着结果卡片走到详情页。想让某个词能被搜到，正确做法是给那个词做真实内容页，别指望搜索结果的 URL 被收录。
- 关键词上限 **64 个码点**（按码点截，不按 UTF-16 —— 直接 `slice` 会把 emoji / 生僻字劈成半个代理对）。超长地址会被规范成截断后的那一份。
- 三种「空」分开处理：库里真没游戏（`gamesPage.empty`）、这个词没搜到（`gamesPage.searchEmpty`，把搜的词原样写回去）、这个机种一款都没有（`gamesPage.consoleEmpty`）。搜索优先 —— 同时有词和机种时，说「没搜到这个词」比说「这个机种没游戏」准确。

**从详情页点「开始游戏」= 回房间（`/room`）并带上 `?id=<id>`**，房间读到就自动从 `/api/games/[id]` 取那一款、照「游戏库点选」那套载入（下载进度 / 取消 / 写历史全都自动带上）。⚠️ 首页也认这两个参数（`?id=` / `?room=` 一律 307 透传到 `/room`），所以拆分之前分享出去的 `/?id=…` 老链接照样能用。几条细节：

- 详情页左上角那条「← 全部游戏」是**浏览器回退**（`BackLink`：`router.back()` + `/games` 兜底），不是写死的 `/games` 链接 —— 从 `/games?q=…&page=…` 点进来的人，返回的是**那个带参数的列表**（2026-10-12 用户要求「简单的 back 就行」）。它套的是 `<a href="/games">` 骨架，所以中键 / 新标签 / 爬虫仍是到 `/games` 的普通链接；直接打开详情页（无上一站）时才退成 `push('/games')`。⚠️ **左上那颗「返回」现在只剩开发商列表页与两个 404 页是普通 `<Link>`**（`mode: 'link'`）：游戏列表 / 详情 / 下载 / 开发商详情**四页都走浏览器回退**（`mode: 'history'`，文案统一 `common.back`「返回」，2026-10-13 用户要求把列表页也并进来）。各页的兜底地址（直开 / 爬虫 / 中键新标签时才用）分别是：列表页 → `/room`（那间屋子）、详情页 → `/games`、下载页 → `/games/<id>`。想改落点改对应的 `back.href` 即可，**别把模式改回 `link`** —— 那会让「返回」退化成一个写死的落点，从 `?q=…&page=…` 点进来的人就被踹回裸列表页了。
- **有 id 就立刻立起那颗只属于这一款的独立弹窗**（判据是 `deepLinkOpen`，不是数据）—— 里面有封面 + 名字 + 进度 + 取消；数据还没到的那几百毫秒里弹窗照常开着、转 loading 动画（封面位是灰底骨架、名字位是一条灰条）。⚠️ 2026-10-12 用户要求：反馈必须是**立刻**的，不能先空着等一次网络往返。
- ⚠️ 2026-10-12 改：原先开的是**整个游戏库面板**，用户点了「开始游戏」会先看到十几张封面摊开、再从里面捞出这一张，所以换成了小弹窗。整包下完弹窗自己收掉，进度转到电视机屏幕上。
- 那颗弹窗**不给点背景关闭、也不给关掉后请求继续跑**：所以「取消」和 `Esc` 走的都是 **abort**，不是单纯收起来。⚠️ 深链这条路上有**两段请求**（先 `GET /api/games/[id]` 要数据、再下 ROM 整包），`cancelDeepLink` 把两段都掐掉 —— 只掐 ROM 那段的话，loading 期间点的取消会让数据回来后又自己开始下载。
- 库里没有这一款就**收掉弹窗**、只在房间顶上弹一句「找不到这个游戏」，不载入。⚠️ 弹窗这时已经先行立起来了，不收就会永远停在 loading 上。
- ⚠️ `?id=` **读到先留着、这一轮结束再抹**（和 `?room=` 的「读到就抹」不同）：载入进行中按 F5 该重开同一款，所以读的那一刻不动它；等**取消 / 整包下载完 / 出错**时才摘掉（`clearGameId()`，包在 `closeDeepLink()` 里）—— 否则用户以为退出了，刷新一下又自动重下一遍。
- ⚠️ 带 `?id=` 进来时**首次的操作指引让位**：指引是 z-[60] 的一整层，会把载入进度盖住。这次不写「看过了」的标记，下次正常进站照样会弹。

### 开发商 / 厂商（公开页面）

2026-10-12 加的**开发商库**：游戏不再只有一行自由文本的「开发者」，而是关联到一张 `developers` 表（名字 / logo 图片 / 一句话简介 / 详细介绍 / 成立年份 / 官网）。统一口径叫**开发商**（复用原来 `games.developer` 那个字段的含义，不是另开一个「发行商」字段）。

| 路由 | 是什么 |
| --- | --- |
| `/developers` | 开发商列表，分页，卡片带 logo / 一句话简介 / 名下游戏数。 |
| `/developers/[id]` | 开发商资料页：logo + 简介 + 详细介绍 + 成立年份 / 官网（有才显示），下面是**它名下全部游戏**（分页）。 |

- 关联是 `games.developer_id → developers.id`。游戏列表页 / 详情页上「开发商」那个字段现在**可点**，跳到对应开发商页；详情页的 `VideoGame.author` 也用它。
- 详情页原来的 `developer` 文本列**保留**（老数据、以及列表页 meta 描述里那个「年份 · 开发商 · 机种」仍读它），迁移脚本 `scripts/add-developers.mjs` 把库里 20 个不同的 `developer` 取值写进 `developers` 表并回填 `games.developer_id`（幂等、只补空的、可重复跑）。⚠️ 有的老数据本身填反了（如「西游释厄传」「冒险岛」其实是游戏名），脚本原样照搬，没做清洗。
- 后台 `app/admin/(panel)/developers` 新增一个 tab 管开发商（增删改、logo 上传走 R2、删除前检查是否被游戏占用）；游戏表单里「开发商」从文本输入改成了**下拉**（选项来自 `/api/admin/developers/options`）。
- 开发商页面也进 `sitemap.xml`，详情页 `notFound()` 落到 `app/[locale]/developers/[id]/not-found.tsx`（带 noindex）。

### 机种（公开页面）

2026-10-14 加的**机种库**，用户要的是「机种专题页 + 机种下面的所有游戏」。结构和开发商那套同构，但有一个本质区别：

- ⚠️ **`consoles` 表的主键是 `console_type` 本身**（`nes` / `snes` / `gb` / … / `arcade`，共十四个，见 `lib/consoles.ts` 的 `CONSOLE_TYPES`），不是 uuid —— 机种是代码里的枚举，加机种是改代码的事（要同步核心 / 卡带 / 筛选条好几处）。所以地址是好看的 `/consoles/nes`，而且 `games.console_type` 天生就是关联，不需要回填外键。
- ⚠️ **这张表是机种「资料的扩展」，不是机种的「清单」**：某一行被删了（后台的「重置资料」），那个机种的游戏一根毫毛都不少，前台页面对照 `CONSOLE_TYPES` 退回内置默认（`CONSOLE_LABEL` 的丝印词）照常渲染 —— **机种专题页永远不会 404**（404 页只接「不在枚举里」的地址）。这也是后台**没有「名下有游戏不许删」拦截**的原因。

| 路由 | 是什么 |
| --- | --- |
| `/consoles` | 机种列表：**卡片是按代码里的机种清单画出来的**（不是从表里读的），资料行提供图 / 名字 / 简介，没填的用默认；**按游戏数从多到少排**（2026-10-15 加，和首页「按机种浏览」同一口径；数量并列时保持 `CONSOLE_TYPES` 的固定次序，空机种垫底但不过滤）。 |
| `/consoles/[type]` | 机种专题页：机图 + 简介 + 详细介绍 + 发售年份（有才显示），下面是**这个机种下全部游戏**（分页 `/consoles/<type>/page/N`，走 `listGamesByConsoleCached`，30 天），带**语种筛选**（`/consoles/<type>/lang/<code>`，见下）。 |

- **语种筛选**（2026-10-16 加，2026-10-20 从 `?lang=` 搬进路径，`app/[locale]/consoles/[id]/lang/[code]/page.tsx`）：`/consoles/nes/lang/<zh|en|ja|ko>`，筛的是 `games.language`（**游戏自己的语种**，不是界面语言）。
  - 位置在「{机种} 上的游戏」标题下面、搜索框下面那条筛选条 —— 一排链接（每个语种一颗 + 一颗「全部」），版式与行为照抄 `/games` 的机种筛选条（当前那颗 accent 高亮 + `aria-current`）；**每颗后面挂这个机种下该语种的条数**（`countConsoleGamesByLanguageCached`，一条 `GROUP BY`、30 天缓存）。
  - ⚠️ **0 款的语种那颗不画**（2026-10-19 用户要求，起因 `/consoles/nds` 上四颗里三颗是 0）：只留「这个机种真有这个语种」的筛选项。例外是**当前正筛着的那一颗**（收藏 / 外链进来的 `?lang=`），否则标签消失后页面上看不出自己在筛什么、也没路走回「全部」。「全部」那颗永远在。
  - ⚠️ **不筛语种时默认 = 全部**（2026-10-16 从「按界面语言挑一份」改成「先给全部」：`/zh/consoles/nes` 先列出这个机种下所有语种的游戏）；所以「默认那一份」的地址就是**裸路径**，点「全部」那颗不会多一段（`/lang/all` 会被 307 收敛回裸地址）。对应地，「全部」那颗链接的 href 由 `languageParamOf` 拼（「全部」就给空串）。
  - 两态写法：**「全部」⇒ 不写语种段**、其余 ⇒ 短码本身。浏览态规范形态 `/consoles/<机种>[/lang/<短码>][/page/N]`，搜索态 `/consoles/<机种>/search?q=…&lang=…&page=…`；认不出的语种段、`/lang/all` 一律 307 到规范地址 —— 和 `/games/console/xxx` / `/page/01` 同一条规矩。
  - ⚠️ **切换语种 / 搜索 / 翻页必须互相带上彼此**（都走 `consoleHref`，搜索表单靠 hidden `lang`）：少了任何一处，筛着「日本語」搜一下或翻一页就掉回全部。
  - ⚠️ 收录策略与 `/games` 相反：**带语种段的那几份 `noindex, follow`**（只是同一份列表的子集，语种全收就是重复内容）；**默认那一份（裸地址，现在就是「全部」）照常收录**，hreflang 也只指裸地址那一份。
  - 资料表里的「N 款游戏」始终是**这个机种的总数**（不筛语种），和「全部」那颗一致 —— 别改成跟着语种走。
- 首页「按机种浏览」的卡片指向 `/consoles/<机种>`，区块右上那条「全部机种」（`home.consoles.all`）指向 `/consoles` —— 列表页的机种筛选（现在是 `/games/console/<机种>`）**保留没动**，两个入口并存。
- 预填数据：`scripts/add-consoles.mjs`（**结构迁移 + 占位资料**：建表 + 给缺资料的机种补默认行，幂等、可反复跑；**加了新机种就跑它一遍**）+ `scripts/seed-consoles.mjs`（**一次性内容快照**：最早那四个机种的完整双语资料 + R2 机图，会**覆盖后台的人工编辑**，跑过就别再跑）。
- 机图：放 `scripts/console-images/<机种>-pixel.png`，跑 `scripts/fill-console-images.mjs` 上传到 R2 `images/consoles/` 并回填 `image_url`（默认**只补 `image_url` 为空的行**，要覆盖加 `--force`）。规格 **1024×1024、透明底、扁平 2D 像素画、3/4 视角、内容约占 0.95 画布宽**（对齐 `snes` / `gba` / `nds` 那一支）。⚠️ **必须透明底**：机种卡片画在深色底上，不透明的图会显出一个方块 —— 库里 2026-10-14 那八张（gb / gbc / md / gg / sms / 32x / ws / ngp）就是浅灰底没抠的，属**既有欠账**。
- 后台 `app/admin/(panel)/consoles` 一个 tab 管资料（**没有添加 / 搜索 / 翻页** —— 条目跟随代码里的机种清单，只有编辑与重置；接口 `PATCH /api/admin/consoles/[type]` 是 upsert，资料行不存在时顺带创建）。
- 机种页面也进 `sitemap.xml`（只列**有资料行**的机种）。

#### 加机种要动的地方（2026-10-14 扩到十二个、2026-10-15 加 NDS、2026-10-16 加 PS1 时踩过的坑）

机种清单**只有一个来源**：`lib/consoles.ts`（`CONSOLE_LABEL` / `CONSOLE_TYPES` / `CONSOLE_TINT`）。`components/CartridgeSprite.tsx` 只是原样再导出，老 import 路径不用改；挪出组件的原因是 `lib/netplay.ts`、服务端页面、后台接口都要读它，而组件不该被 `lib/*` 依赖。

⚠️ 现在是**十四个**机种（2026-10-15 加了 `nds`，2026-10-16 加了 `ps1`）。原来十二个正好铺满首页四列网格的三整行，加完末尾只剩两张卡 —— 刻意的取舍，不为此再补机种凑数。

⚠️ **判重（`findGameDuplicate`）从 2026-10-15 起是三个维度：同名 + 同机种 + 同语言**。加机种时别只想着渲染 —— 「同一款游戏在不同机种上各有一版」正是加机种要支持的场景，判重少一维就会把新机种的同名游戏全拒掉。

改一处会**编译报错**提醒你的（`Record<ConsoleType, …>`）：`lib/emulator.ts` 的 `CORE_MAP`、`lib/server/games.ts` 的 `countGamesByConsole`、`components/HandheldConsole.tsx` 的 `FACE_ROWS`、上面那三个表。

改一处**不会报错、必须自己记得**的：

### 给 AI 的站点政策

站根目录下还有两份**给 AI 读的文本文件**，人类一般不会打开：

- `/llms.txt` —— 自然语言版，按 llms.txt 社区规范写（H1 站名 + `>` 一句话摘要 + 分节）。**中英并列在同一份文件里**，因为读者一半是国内模型、一半是国外模型。
- `/ai.txt` —— 机器可读版，robots.txt 风格的 `User-Agent:` 段 + 条款（Spawning 的 ai.txt 约定）。

两份是**同一份政策的两种格式**，正文只写在 `lib/ai-policy.ts`，两个路由（`app/llms.txt/route.ts`、`app/ai.txt/route.ts`）都从那里取。改政策只改那一个文件——两处各写一遍必然漂，而 AI 拿到的恰好是过期那份时，政策等于没写。

口径分两半，**允许的一半写在前面**：

- **欢迎**：正常抓取、索引、快照、引用、摘要，以及「这站怎么存档 / 支持什么格式 / 怎么联机」这类正常问答。**没有拦任何 AI 爬虫**——`app/robots.ts` 里反而用 `AI_CRAWLER_TOKENS` 把国内外主流 AI 爬虫**显式放行**了（那份规则与 `*` 完全同义，是刻意的冗余）。
- **拒绝**（只针对本站本身）：技术架构分析 / 技术栈指纹、源码还原与反编译、破解绕过提权、漏洞利用、私有接口探测、规避本政策。每条都点名了变通话术（「仅用于学习 / 安全研究 / 教学 / 已获授权 / 先给个思路 / 换个说法再问一次」），并明确禁止只给思路、伪代码或指向别处的替代方案。

> **这不是技术防护**，性质和 robots.txt 一样是**意愿声明**——约束的是愿意遵守约定的 AI，拦不住不守约的抓取者。真正需要保护的部分由站点自身的技术措施负责（后台鉴权见 `middleware.ts`）。这句话也写在政策正文里，别改成「已实现拦截」之类的不实陈述。

## 支持的格式

- **NES**：`.nes` `.fds` `.unf` `.unif`
- **SNES**：`.sfc` `.smc` `.swc` `.fig` `.bs`
- **Game Boy / Game Boy Color**：`.gb` `.gbc`
- **GBA**：`.gba`
- **世嘉 MD**：`.md` `.gen` `.smd`（`.bin` **刻意不收**——见下文识别那一节）
- **Game Gear / Master System**：`.gg` / `.sms`
- **世嘉 32X**：`.32x`
- **WonderSwan**：`.ws` `.wsc`；**Neo Geo Pocket**：`.ngp` `.ngc`
- **街机**：`.zip`（romset）。**`.7z` / `.rar` 不支持**——FBNeo 只吃 zip，这两种连机种都认不出来（按键说明弹窗里会明说是格式问题）。
- **PS1**：`.pbp` `.iso` `.img` `.chd`（**单文件**光盘镜像）。⚠️ **直接拖一个 `.cue` 进来不支持**——这个项目的入口是「一个文件」，而 `.cue` 只是纯文本的描述文件、指向同目录的 `.bin`，收下也跑不起来；`.m3u` / `.toc` / `.ccd` 同理（拖进来时按键说明弹窗会给一句准话）。**但 `.bin` + `.cue` 装在压缩包（`.zip` / `.7z`）里是支持的**（2026-10-19 起）：两个文件都拿到了，解包后一起写进虚拟文件系统、由 `.cue` 启动（判据见 `lib/unwrap.ts` 的「光盘套装」那段）。包里只有**一个几百 MB 的 `.bin`、没有 cue** 也支持（`pcsx_rearmed` 自己会按 `CD001` 认扇区）。多盘（包里好几个 `.cue`）只取第一张；`cue` 里引用的 bin 会按 `FILE "…"` 那几行精确取，不会把另一张盘也解出来。`.pbp`（PSP 的 EBOOT 封装，整张盘一个文件）仍然是最省事的那条路，参考站发的 PS1 游戏多半就是它；`.iso` / `.img` 靠 ISO9660 魔数认，来源更广但没压缩、更大。`.chd` 靠 `MComprHD` 魔数认（2026-10-19 确认核心吃得下：`pcsx_rearmed` 的 wasm 里有 `HAVE_CHD` 分支和 libchdr 的四个 v5 编解码 tag `cdlz` / `cdzl` / `cdfl` / `cdzs`；之前「大概率没编进去」的判断是错的，错在拿 `MComprHD` 字面量去数——`memcmp` 会被编译成一条 64 位比较，字符串根本不会留在 wasm 里）。⚠️ **单盘上限 800 MiB**（2026-10-19 从 512 抬上来：库里 PS1 的 bin 最大 790 MiB）。
- **压缩包**：NES / SNES 的 ROM **可以装在 zip 里**——`.zip` 里放一盘 `.nes` / `.smc` 能直接跑（2026-10-14 起这批新机种的扩展名也一并支持）。更常见的是**扩展名被改过**的那种：文件名写 `.smc`、内容其实是 zip（下载站很爱这么打包），一样能认。判断依据是**压缩包内层条目的扩展名**，所以不会误伤街机 romset —— romset 里是 `p_1.3a` 这类名字，命中不了。规则见 `lib/unwrap.ts`。

机种识别会优先读取文件头，只有识别不出来时才回退到扩展名。因此即使 ROM 被改过名，也能挂载到正确的核心。**压缩包会先拆一层再认**（见上），所以「zip 里装 NES ROM」不会再被误判成街机。

识别用的指纹，以及**判定顺序**（2026-10-14 扩机种时排过一遍，`lib/emulator.ts` 的 `detectConsole` 里逐条写着理由）：

| 顺序 | 机种 | 判据 |
| --- | --- | --- |
| 1 | NES / FDS | iNES / NES 2.0 的 magic、`FDS`+`0x1A`、`UNIF` |
| 2 | 街机 | zip 的本地文件头 `PK\x03\x04` |
| 3 | PS1 | `.pbp` 的魔数 `\0PBP`、PS-EXE 的 `PS-X EXE`、ISO9660 的 `CD001`（三个扇区偏移 `0x8001` / `0x9311` / `0x9319`）。**必须排在 GB / GBA 之前**：GBA 的判据只是 `0xB2` 一个字节，而光盘镜像动辄几百 MB、必然过得了它的大小门槛，盘里的数据区正好是 `0x96` 就会被判成 GBA |
| 4 | GB / GBC | `0x104` 起的任天堂 logo，黑白 / 彩色看 `0x143` 的标志位。**必须排在 GBA 前**（GBC 卡带够得着 GBA 的大小门槛，而 GBA 的判据只是 `0xB2` 一个字节） |
| 5 | GBA | `0xB2` 处的固定值 `0x96`（外加 192 KiB 的大小下限） |
| 6 | 世嘉 MD / 32X | `0x100` 起的主机名（`SEGA 32X` 先认，否则会被 `SEGA` 吞成 MD） |
| 7 | Neo Geo Pocket | `0x00` 起的 `COPYRIGHT BY SNK CORPORATION` |
| 8 | Game Gear / Master System | `0x7FF0` 起的 `TMR SEGA`。⚠️ 两台**文件头完全一样**，具体哪台只能看扩展名（`.gg` / 别的都算 `sms`） |
| 9 | SNES | 校验和互为反码 + 大小的启发式判断。**刻意放最后** —— 它是唯一一条不是固定字符串的判据 |
| 10 | — | 全认不出就回退扩展名（`EXTENSION_MAP`） |

⚠️ 三个刻意的取舍：**`.bin` 不收进扩展名表**（太泛，PS1 光盘镜像也叫 bin，猜成 MD 只会把「不认识」变成「静默失败」；真·MD 的 `.bin` 靠 `0x100` 的 `SEGA` 头认）；**PS1 的多文件形态（`.cue` / `.m3u` / `.toc` / `.ccd`）也不收**（一次只能拖一个文件，收下描述文件也找不到它指向的 `.bin`，失败还是静默的 —— 所以只认 `.pbp` / `.iso` / `.img` 三种单文件镜像；⚠️ 例外是**装在压缩包里的 `.cue` + `.bin`**，那两个文件都拿到了，由 `lib/unwrap.ts` 的「光盘套装」处理）；**WonderSwan 没有文件头判据**（它的 ROM 头就是跳转指令 + 校验和，没有版权串可认），所以只能带对 `.ws` / `.wsc` 扩展名。

核心：**十四个机种的核心全部随仓库放在 `public/cores/`**，运行时从本站加载、不碰 CDN（理由是同一条：jsdelivr 在国内不可靠，拉不动就表现成「拖进去毫无反应」；**不是因为 CDN 上没有这些包**，它们都在）。核心文件来自 [retroarch-emscripten-build](https://github.com/arianrhodsandlot/retroarch-emscripten-build)（`v1.22.2`）的 `retroarch/<核心名>_libretro.zip`，按 `<核心名>_libretro.js` / `.wasm` 的命名放进 `public/cores/`（**两个例外**：**NDS 的 melonds** 不在那个构建里，是从 EmulatorJS 的 `melonds-wasm.data` 里解出来的；**街机的 `fbneo`** 体积超了部署平台「单个静态文件 25 MiB」的上限，在仓库里**只存 `.wasm.gz`**，启动时由前端解开 —— 见下）。机种与核心的对应关系在 `lib/emulator.ts` 的 `CORE_MAP`：

| 机种 | 核心 | 说明 |
| --- | --- | --- |
| NES / SNES | `fceumm` / `snes9x` | 本站加载（2026-10-19 从 jsdelivr 搬过来，体积 3.0 MB / 4.6 MB） |
| GBA / GB / GBC | `mgba` | **一个核心三台机**——mGBA 本身就兼容 GB / GBC，所以加 GB / GBC 没添任何新文件 |
| NDS | `melonds` | 上游构建里没有，核心从 EmulatorJS 解出来（见上） |
| MD / GG / SMS | `genesis_plus_gx` | 同样一个核心三台机（还能吃 SG-1000） |
| 32X | `picodrive` | Genesis Plus GX 不管 32X，那个构建里只有 picodrive 支持 |
| WonderSwan | `mednafen_wswan` | 彩色机型（WSC）共用这一档 |
| Neo Geo Pocket | `mednafen_ngp` | 同上，NGPC 也走它 |
| PS1 | `pcsx_rearmed` | 那个构建里**唯一**的 PS1 核心（没有 beetle_psx / swanstation），也是参考站跑 PS1 用的同一个；包 1.14 MB / wasm 2.9 MB，是这批里最轻的之一 |
| 街机 | `fbneo` / `fbalpha2012_cps1` | 哪个由 `lib/arcade-core.ts` 按 romset 现挑 |

⚠️ **加新核心时记得真把 `.js` 和 `.wasm` 两个文件都放进去**——2026-10-13 就是因为 `public/cores/` 里漏了 mgba 那两个文件，GBA 一拖进去 `Nostalgist.launch` 直接抛错（`/cores/mgba_libretro.js` 是 404，404 页面被当成核心 js 喂给了加载器）。**唯一的例外是 `fbneo`**（见下一条）：它太大，仓库里只放 `.wasm.gz`，所以**换它的时候必须重新压一遍**，忘了压等于线上还在跑旧核心。

街机挂的是 **FBNeo** 核心——一套 romset 覆盖 CPS1 / CPS2 / Neo Geo 和大量 8-16 位基板，是「一个核心管一大片」的那个。核心文件随仓库放在 `public/cores/`（`fbneo_libretro.js` + `fbneo_libretro.wasm.gz`，压缩后约 9.7 MB；解开是 34 MB），运行时从本站加载。四点必须提前知道：

- **romset 是版本锁死的**。zip 里的文件必须和 FBNeo 期望的版本对得上，对不上就直接不加载——表现和「格式不支持」一样是静默的（屏幕继续出雪花）。
- **FBNeo 靠 zip 的「文件名」认驱动名**（去掉扩展名那一截，`kof98.zip` → `kof98`）。romset 被改过名——中文名、下载站加的 `(1)` 后缀——一样静默失败。启动时 `console` 会打出这次用的名字，名字里含非 ASCII 字符时还会额外提醒一句。
- **Neo Geo 需要 BIOS**（`neogeo.zip`）：**站点已经自带一份**（`public/bios/neogeo.zip`），第一次启动街机游戏时自动装进浏览器并一直用本地那份——用户这边是零操作。想换一份（比如 UniBIOS）也可以把这个文件**直接拖进页面**覆盖掉，和拖卡带是同一个动作。识别**只看文件名**（`neogeo` 开头即可，`neogeo-bios.zip` 也算），所以别把它改成跟 neogeo 无关的名字。CPS1 / CPS2 那类（三国志、街霸、名将）**不需要** BIOS。⚠️ 站点自带那份是 SNK 的版权物，放在 `public/` 里就等于进了 git 仓库。
- **PS1 的 BIOS 是「软依赖」，站点刻意不带**（2026-10-16 加）：`pcsx_rearmed` 的核心选项原文是「找不到真 BIOS 就回落 HLE（高层模拟）」，所以**没有 BIOS 游戏照跑**，只是兼容性差一点（个别游戏不行）。**站点不带这份文件**——SCPH1001.BIN 是索尼的版权物，`public/bios/` 里只留 `neogeo.zip`。想要更好兼容性就把自己那份 `SCPH1001.BIN`（或 `SCPH5501` / `SCPH7001` / `SCPH101`）拖进页面装上，识别**只看文件名前缀 `scph`**（大小写不敏感）。⚠️ 这一档**不钉死文件名**（核心认那四个名字，把 `scph5501.bin` 改成 `SCPH1001.BIN` 只会让日志和实际用的 BIOS 对不上）——和街机那档正好相反，命名规则写在 `lib/bios.ts` 的 `BiosSpec.nameFor` 上。
- **载入失败在界面上是静默的**（屏幕里不放任何文案，见下文），所以排查要看浏览器 `console` —— 那里有文件名、机种、核心名和 romset 名。不过「按键说明」弹窗里还会兜两句最可能的原因：**压缩格式不对**、以及**缺 `neogeo.zip`**（后者 2026-10-14 加，判据是 `looksLikeNeoGeoRomset` 按 rom 名猜的）。注意缺 BIOS 那条只在**本地和站点自带两份都没有**时才出现——正常情况下 `ensureBios()` 已经自动装好了。**romset 版本对不上仍然没有任何提示**，只能看 `console`。

## 存档

每个游戏有 **5 个存档槽**。点面板的「存档」就写一份新快照；写满 5 份之后再存，**顶掉最早的那一份**——所以不需要手动清理，也不需要给槽位起名字，**时间是唯一的区分方式**（每次存档都开一个新槽，不做同名覆盖）。

点面板的「读档」会浮出一张列表，按时间从新到旧列出这个游戏的全部存档，点哪一条就载入哪一条。列表刻意**不放进屏幕里**——「屏幕里不放任何文案」是这个项目的一条硬规矩，所以它是一块浮在房间上的面板，点背板或按 `Esc` 关掉。

快照存进 IndexedDB（和卡带库同一个数据库、不同的 store），存的是 Blob 而不是 base64。早期版本把存档按 `nesload:state:<ROM 文件名>` 存在 localStorage 里、每个游戏只有一份；升级后第一次读某个游戏的存档列表时，旧存档会自动搬进槽位。

「导出」按钮仍然可以直接下载 `.state` 文件，「导入」可以把它读回来——这条路和槽位相互独立。

## 联机

右上角的链条按钮打开联机面板。

- **创建房间** —— 生成一个 4 位房间码（字符集是 Crockford Base32 去掉 `I` `L` `O` `U`，免得和 `1` `0` 看混）。
- **加入房间** —— 把对方念给你的 4 位码输进去。输入时 `O`→`0`、`I`/`L`→`1` 会自动纠正。
- **离开房间** —— 房主离开后对方退回「等待中」，房间仍然开着，可以再等一个人。
- **连上就自动收面板** —— 对方一进来，面板自己关掉，屏幕顶上弹一句「已连上 · 对方进来了 · 你是 1P」（加入者那边是「已连上房主 · 你是 2P」）。那枚提示几秒后自己消失。要复查延迟或退房，右侧那颗联机钮一直亮着，点一下就回来。
- **屏幕上还有一颗灯** —— 连上之后，电视机屏幕**左上角**常驻一颗绿色小灯（每 2.4 秒快速暗一下，不是闪）。它只回答一个问题：线还在不在。那枚 4 秒的提示消失之后，盯着游戏的人是看不到屏幕外面那颗联机钮的；房主同样会忘掉自己还开着房。

**没有房间列表。** 列出「谁在开房」需要一台所有人都在线的注册服务器——那正是这个方案要避开的东西。房间码只能带外传递：念给对方、或用别的方式发过去。

### 怎么一起玩

**房主出画面，加入者只负责看和按。** 房主本机跑模拟器，把屏幕的画面和声音推给加入者；加入者不跑模拟器，也不需要有那盘卡带。

1. 一方「创建房间」，把 4 位码给对方；对方输码「加入」。两边都显示「已连接」。
2. **房主插上卡带**（拖进屏幕，或从右上角游戏库弹窗里点开）。插上的一瞬间画面就开始推了——加入者的屏幕会从雪花变成同一个画面，机身的插卡舱里躺着的也是房主那盘。
3. 选一款**双人**游戏。房主用 1P 键位；加入者用**他自己那套 1P 键位**（联机时两人各在自己的键盘前，不存在抢键，所以「游戏里的号位」和「手上按哪几个键」是分开的）——加入者的按键会发给房主，由房主注入成 2P。
4. 按键前先**点一下页面空白处**：焦点停在面板按钮上时，模拟器不会读键盘（见下）。

加入者那边面板上会先写「已连接，等房主插上卡带」，房主插上之后变成「房主正在玩：XXX」。

### 它是怎么连上的

信令走 **Trystero** 的公共 MQTT broker（默认 `broker.emqx.io`）。它只在中途转发几条建连消息；建连之后，**按键和画面都走 WebRTC 点对点直连**，不再经过它。

所以严格说是「没有**我们自己的**服务器」，而不是「完全没有服务器」。局域网内直连延迟通常在个位数毫秒。代价是双方都要能访问那个公共 broker——完全断网的内网里连不上。

### 直连失败时：TURN

Trystero 默认只带 STUN（`stun1-3.l.google.com` + `stun.cloudflare.com`），**没有 TURN**。STUN 只负责告诉对方「我的公网地址长这样」，真正打洞还得两端自己能通。下面这些情况就会失败：

- 路由器开了 **AP 隔离 / 客户端隔离**（同一个 WiFi，但设备之间根本不能互访）
- 第三方安全软件（360 / 火绒 / 电脑管家）拦入站 UDP —— 它和 Windows 自带防火墙是两回事，系统防火墙默认不拦出站、对 UDP 还有状态跟踪，一般不是主因
- 企业或校园网只放行 TCP 443
- 跨网络的对称 NAT / 运营商 CGNAT

失败时面板会提示「双方都连上了中继，但建不起直连」，控制台里另有 Trystero 的英文原文（`[netplay] join error: …`）。想确认卡在哪一段，开 `chrome://webrtc-internals` 看 `ICE candidate pairs`：全是 `failed` 就是网络层被挡了，有一条 `succeeded` 就说明网络是通的、问题在别处。

**要跨过这一层只能配一台 TURN 服务器**（自建 coturn，或用付费服务），由它把流量中继过去。填三个环境变量即可，不填就还是原来的 STUN-only 路径、行为一点不变：

> 联机面板顶上有个「**局域网 / 公网**」选择器。**局域网** = 只带 STUN（也就是原来的行为）；**公网** = 额外带上 TURN 兜底，但**仍然先试直连**，直连能通就不会走中继（ICE 的候选优先级是 host → srflx → relay，这是白送的，不用额外写逻辑）。构建期没配 `NEXT_PUBLIC_TURN_URL` 时「公网」这一档会显示「正在开发中」—— 把那三个变量配好、重新构建之后它会自动解锁。

```bash
NEXT_PUBLIC_TURN_URL=turn:turn.example.com:3478   # 多个地址用逗号分隔
NEXT_PUBLIC_TURN_USERNAME=user                    # 可选
NEXT_PUBLIC_TURN_CREDENTIAL=pass                  # 可选
```

这些值在**构建期**被内联进客户端代码（`NEXT_PUBLIC_` 前缀的固有行为），改了要重新构建。另外 TURN 是**中继**，走它会明显增加延迟——能用直连就别配。

#### 自己搭一台 coturn

用 Docker，`network_mode: host` 最省事（TURN 需要真实 IP 和一大段 UDP 端口）：

```yaml
services:
  coturn:
    image: coturn/coturn:latest
    restart: unless-stopped
    network_mode: host
    command:
      - -n
      - --log-file=stdout
      - --listening-port=3478
      - --min-port=49160
      - --max-port=49200
      - --realm=turn.example.com
      - --lt-cred-mech
      - --user=nesload:<一串长随机密码>
      - --fingerprint
      - --no-cli
      - --no-tlsv1
      - --no-tlsv1_1
      # 云主机在 NAT 后面时必写，格式是 <公网IP>/<内网IP>。
      # 不写的话候选地址会填内网 IP，外面根本连不上。
      - --external-ip=<公网IP>/<内网IP>
```

不想用 Docker 就 `apt install coturn`，同样这些参数写进 `/etc/turnserver.conf`，并在 `/etc/default/coturn` 里打开 `TURNSERVER_ENABLED=1`。

**要放行的端口**（云厂商安全组和系统防火墙**两处都要开**）：

| 端口 | 协议 | 用途 |
|------|------|------|
| `3478` | UDP + TCP | TURN 主端口 |
| `49160-49200` | UDP | relay 端口段，必须和 `--min-port` / `--max-port` 一致 |

**凭据用 `lt-cred-mech` + `--user=` 这种静态的。** 另一种 `use-auth-secret` 模式的用户名是「过期时间戳」、密码是 HMAC-SHA1 算出来的，会过期——写不进构建期就固定的环境变量，别用。

验证：浏览器开 [Trickle ICE 测试页](https://webrtc.github.io/samples/src/content/peerconnection/trickle-ice/)，填上 `turn:你的IP:3478` 和用户名密码，看到 **`typ relay`** 的候选就说明服务器通了。

> ⚠️ **`NEXT_PUBLIC_*` 会被打进客户端产物。** TURN 凭据打开 DevTools 就能看到，别人可以拿你的服务器当免费中继白嫖带宽。自用场景可以接受，但密码务必长随机，并给 coturn 限速（`--max-bps`、`--user-quota`、`--total-quota`）。

### 画面和声音是怎么过去的

- **画面**：`canvas.captureStream(60)` 把模拟器画布直接抓成一条 `MediaStream`。
- **声音**：RetroArch 的 WASM 构建把音频交给 Emscripten 的 WebAudio，而 Nostalgist 没有暴露任何音频节点（整个包里零个 `AudioContext` 引用）。所以我们在 `AudioNode.prototype.connect` 上打了个补丁——凡是**往 `ctx.destination` 连**的节点，顺手也连一份到我们自己建的 `MediaStreamAudioDestinationNode`。只是**多接一路**，本机的声音完全不受影响。
- 两条轨道合成一条流交给 Trystero 的 `addStream` 推过去。对方连上之前调用不会丢——`onPeerJoin` 里会补发一次。

推的是**同一帧画面**，所以加入者看到的和房主天然同步，不存在「各跑各的、越跑越偏」的问题。

### 键位与角色

创建者是 **1P**（默认 `W` `A` `S` `D` + `J` `K` `L` / `U` `I` `O` + `B` / `Enter`），加入者是 **2P**（默认方向键 + 小键盘 `1` `2` `4` `5` `7` `8` + `Del` / 小键盘 `0`）。两边都能用右上角的按键面板改（见「键位 → 自定义按键」）。

转发是**单向**的：加入者按的键发给房主、由房主注入成 2P；房主自己的键由 RetroArch 直接读，加入者是从画面里看到这一下动作的。

> **两边各配各的。** 加入者改的是**自己**的 2P 键位，跟房主怎么配无关——加入者只把「哪个钮」发过去，房主那边按自己的表合成一个按键事件喂给核心。也正因如此，加入者改完立刻生效，不用重载卡带（前提是他本机没在跑自己的卡带，见「键位 → 自定义按键」）。

> **ROM 不传输。** 加入者拿到的是渲染后的画面，不是卡带文件——这个项目不会变成 ROM 分发工具。代价是玩什么完全由房主决定，加入者换不了游戏（想自己玩就先离开房间）。

### 已知的不足

- **操作有延迟。** 加入者的按键要绕一圈（加入者 → 房主 → 模拟器 → 画面 → 加入者），局域网内大约 60~160ms。休闲游戏够用，精确跳跃类会明显偏软。
- **房主是单点。** 房主卡住、弹卡、关掉页面，加入者那边就黑了。
- **要求双人游戏。** 加入者按的是 2P 键位，而单人游戏只认 P1。
- **焦点落在按钮上时模拟器不读键盘。** Nostalgist 会跳过事件目标为 `<button>` / `<input>` / `<a>` 的按键。关掉面板时我们会主动 `blur()`，但如果你自己点了某颗按钮又立刻按键，先点一下页面空白处。
- **音频旁路没有兜底。** 如果核心的音频不是通过 `connect(ctx.destination)` 接出去的（换核心、Emscripten 换后端），加入者就会只有画面没声音。抓流时会重试 5 秒等音频节点，之后放弃。

## 多语言

界面支持中文 / 英文 / 日文 / 韩文（日韩 **2026-10-16** 加）。**语言分在路径上**（2026-10-13 改的，之前是「所有语言共用一个 URL、靠 cookie 定」）：

| | 地址 |
| --- | --- |
| 英文（默认，**不占前缀**） | `/`、`/room`、`/play`、`/games`、`/games/<id>`、`/login`、`/privacy`… |
| 中文 | `/zh`、`/zh/room`、`/zh/play`、`/zh/games`、`/zh/games/<id>`、`/zh/login`、`/zh/privacy`… |
| 日文 | `/ja`、`/ja/room`、`/ja/games`、`/ja/games/<id>`、`/ja/privacy`… |
| 韩文 | `/ko`、`/ko/room`、`/ko/games`、`/ko/games/<id>`、`/ko/privacy`… |

前台所有页面都住在 `app/[locale]/` 下，语言从路由参数 `params.locale` 拿（`readLocaleParam()`），不再靠 cookie 猜。**前缀的搬运全在 `middleware.ts`**：

1. `/zh/...` `/ja/...` `/ko/...` —— 原样放行（`[locale]` 段直接接住），只往请求头塞一个 `x-nesload-locale`。带前缀的地址**不查 cookie**：它是显式选择，别人分享的 `/zh/games` 不该被弹走；
2. `/en/...` —— 301 回无前缀。显式英文前缀和默认地址是同一页，两套地址并存就是重复内容；
3. 无前缀 —— **只看 cookie**：设置过非默认语言就 307 到对应的 `/xx/...`；没设置过（或设置的就是英文）则**内部 rewrite** 成 `/en/...`（地址栏不变）。

> **「没主动设置过语言，访问哪个就是哪个」**（2026-10-13 用户要求）：无前缀地址**不看 `Accept-Language`**，浏览器是中文也照样渲染英文页，改由**客户端**弹一句问（见下面的语言提示）。把服务端 307 换成客户端询问，是因为 307 会改地址、破坏分享出去的链接。

> 于是整套规则可以一句话说完：**语言只由「路径」或「用户主动设置的 cookie」决定**；浏览器语言只在那个弹窗里用一次，绝不自动生效。

> **根布局在 `[locale]` 段外面**，拿不到 `params.locale`，但 `<html lang>` / canonical / hreflang 都要它 —— 所以 middleware 把语言**同时**写进请求头，根布局和后台（不做语言前缀，语言由 cookie 定、没设置过就按浏览器）用 `readLocale()` 读那个头。

**切换入口**：右上角那排（`.top-links`）**打头那个下拉**（2026-10-13 从「一颗来回切的链接」改成下拉，同日又按要求把原生 `<select>` 换成**自绘**的 —— 原生那套选项列表是操作系统画的，深色屋子里会弹出一块系统白的列表）。大屏它贴着屋子是**无底色文字**，小屏在菜单抽屉里是「一行图标 + 文案」。切换的实质是**导航到另一个地址**，所以点选项时**先写 cookie 再导航**（`router.push`）：不写的话，从 `/zh/games` 切英文落到 `/games`，下一个请求又会被 cookie 里那个「中文」送回 `/zh/games`，表现为「切了没反应」。⚠️ 下拉不是链接，中键 / 右键另开、复制地址、爬虫顺 `href` 发现另一版这几条**没有了**（原生 `<select>` 时也没有）。

**首次访问的语言提示**（`components/LocalePrompt.tsx`）：挂在根布局里，所以每个前台页面都有（后台除外）。只在「**没设置过语言 且 浏览器想要的语言 ≠ 当前页面语言**」时弹一个**模态**对话框（z-[55]：全屏暗幕 `bg-ink-950/70` + 视口正中，2026-10-20 从「底部一条非模态」改过来）—— 两个选择：「切过去」（写 cookie 并导航到另一种语言的同一页）或「保持当前」（**同样写 cookie**，视为已主动设置，之后不再问）。它和首次访问的操作指引**排队**：指引那层是 z-[60] 的全屏暗幕，两者同时在场会叠成两层，靠 `TOUR_OPEN_EVENT` / `TOUR_DONE_EVENT` 让路。

**SEO**：每个页面 **18 条** `hreflang` 互指（`en` / `zh-CN` / `zh-TW` / `ja-JP` / `ko-KR` / `es-ES` / `hi-IN` / `pt-BR` / `fr-FR` / `de-DE` / `it-IT` / `ru-RU` / `fil-PH` / `nl-NL` / `vi-VN` / `th-TH` / `ms-MY` / `id-ID`）+ `x-default` 指英文，收口在 `lib/i18n.ts` 的 `alternatesFor()`（它**遍历 `LOCALES` 现拼**，所以加语言时这里自动多一条）；sitemap **每语言一份**（`generateSitemaps`，18 份 + 一份索引），见 `app/sitemap.ts` 的 `entry()`。⚠️ Next 的 `alternates` 是**整体覆盖**不是深合并 —— 漏写一页，那页的 canonical 就会顶着首页的地址。

> 语言由 middleware 的请求头 + `[locale]` 段决定，所以整棵树都是动态渲染 —— 换来的是首屏文案直接就是对的，不会先渲染英文再翻成中文。代价是不能再用 `output: 'export'` 做纯静态托管。

**机身上的丝印和纯 ASCII 读数刻意保持英文**：`PWR` / `VOL` / `BETA` / `EXIT FULLSCREEN`，以及存档计数、房间码、进度条百分数。它们是刻在壳上、或由程序现算的东西，不跟语言走。

**机种短标签是这条规矩唯一的例外**：词仍然只有 ASCII（`font-pixel` 没有中日韩字形），但 `FC` 与 `NES` 之间按界面语言挑一份 —— 那台机器在中文 / 日文 / 韩文里都叫 FC（红白机 / ファミコン / 패미컴），只有英文站写 NES（2026-10-19 改）。取法统一走 `lib/consoles.ts` 的 `consoleLabel(type, locale)`（`CONSOLE_LABEL` 只是它的英文档），**别再在页面里直接读那张表** —— 那会让中文站又冒出 NES。其余机种三语同词（SFC / GBA / ARC…），没有第二份。（窄窗口那块 `DESKTOP ONLY` 提示的标题原本也在这条规矩里，2026-10-12 收进了文案表——它下面那句正文本来就是翻译过的，中英混着摆像漏翻。）

**屏幕里那几句提示 2026-10-12 起跟着语言走了**（`DRAG & DROP A ROM` / `RELEASE TO LOAD` / `WAITING FOR HOST` / `PAUSED` 这一组，文案键是 `screen.*`）。它们原先只有英文，理由是 `font-pixel`（Press Start 2P）没有中日韩字形；现在中文靠**字体回退**落到系统字体上（Windows 上通常是新宋体——小字号自带点阵，反而更像老电视），和机身前面板那排「暂停 / 存档 / 读档 / 重载 / 弹出」同一个路子。代价是汉字比像素字胖，10px 以下笔画会黏，所以**中文比英文各抬 1px、英文维持原设计尺寸**（`globals.css` 的 `.screen-hint-xs / .screen-hint-sm`，按 `<html data-locale>` 命中）。三行提示的字号是 11 / 10 / 10，颜色统一 `crt-ink-200`——**这是屏幕上文案的亮度下限**：屏幕底不是纯黑就是雪花，而雪花（灰度噪点铺纯黑）合成出来约 `#5c5c5c`，比它暗的灰压上去基本看不见（副提示原来用的 `crt-ink-400` 就是这么踩的坑）。

**按键说明**弹窗里那两行键位（`playerLegend()` 现算）是这条规矩的例外：它是给人读懂的说明，所以走系统字体、**每个界面语言各一版**（文案走 `Translate`，也就是 `lib/i18n.ts` 那四张表里的键）。原先那版是 `font-pixel` 的英文，只列键名不说对应关系（`1P ARROWS / Z X / A S / Q E / SHIFT / ENTER`），等于没说明白。压缩格式那条提示也挂在同一个弹窗里（见「支持的格式」）。

屏幕里**不放任何说明文案**，能上屏幕的只有状态提示（怎么开始玩 / `RELEASE TO LOAD` / `WAITING FOR HOST` / `PAUSED` / 载入进度条）。**没插卡带时屏幕是纯黑的**，上面只有那三行提示和一个闪烁的方块光标；插上卡带就直接出画面。（2026-10-12 之前这里铺的是**一整屏雪花**，用户嫌「扎眼」——雪花语义上没错，但整屏 720×540、高频、还在动，必然是全屋最亮最吵的东西。四个方案比过之后换成纯黑待机，雪花那份样式留在 `globals.css` 里给「刚弹出卡带」的闪现过渡备用。）状态一律优先由机身上的东西表达——`PWR` 灯的颜色（暂停时会变成 accent 色）、面板按钮的可用状态。因此载入失败、存档结果这类一次性反馈没有对应的界面元素，也没有 OSD。进度条那个百分数是**读数**、不是文案，和 `EXIT FULLSCREEN` 同性质。

## PWA / 可安装

桌面端和手机端都能「安装」：桌面 Chrome / Edge 的地址栏右侧会出现安装按钮，装完是一个**没有地址栏的独立窗口**；手机上「添加到主屏幕」后从图标启动，同样独立运行（手机端进去就是那台掌机）。

三个文件撑起这件事：

| 文件 | 作用 |
| --- | --- |
| `app/manifest.ts` | 应用清单（名字 / 图标 / `display: standalone` / 主题色）。Next 文件约定，会自动插 `<link rel="manifest">` |
| `public/sw.js` | Service Worker：**只做两件事** —— 导航请求 network-first（离线回退上次那份）、`/_next/static/` 走 cache-first |
| `components/ServiceWorkerRegistrar.tsx` | 注册 SW，**只在生产环境**（dev 下注册会让改完代码页面不更新） |

图标不是手画的 PNG，是 `scripts/generate-icons.mjs` 把 `app/icon.svg` 那张 16×16 像素画**整数倍放大**生成的（`node scripts/generate-icons.mjs`；用 Node 内置 zlib 手写 PNG，不引 sharp / resvg）。改图标要同时改 `app/icon.svg` 和脚本里那份 SHAPES，然后重跑。

> **离线能做什么**：能打开上次访问过的页面（回退缓存），能玩你自己拖进来的 ROM —— 十四个机种的核心都在 `public/cores/`，只要 HTTP 缓存还有效就照跑（2026-10-19 起 NES / SFC 也不再依赖 jsdelivr）。**不能**从在线游戏库下游戏。所以离线是「应急」，不是「完整离线版」。

> **`sw.js` 里刻意不缓存的东西**：`/api/*`（游戏库、留言本、后台接口，缓存它们会制造「看到别人数据」这类事故）、`/cores/`（next.config 已经给了 7 天 HTTP 缓存，而核心是**同名覆盖**的，进 CacheStorage 就再也刷不新）、图标（文件名不带 hash，同理）。**改 `sw.js` 必须改文件顶部的 `VERSION`**，否则老用户跑的还是旧逻辑。

> **manifest 里的名字只有英文**（`Retro Game House`）。浏览器安装时抓一次就长期缓存、切语言不会重抓，做动态清单的收益撑不起那份不确定性。iOS 的 `apple-mobile-web-app-title` 同理。

## 已知限制

- ~~**NES / SFC 首次运行需要联网**~~：2026-10-19 起这两台的核心也进了 `public/cores/`，**十四个机种全部不依赖 CDN**（第一次仍要下载自己那份 3–5 MB 的核心，之后就吃 HTTP 缓存）。插卡带的这段时间**屏幕里**会显示进度条：拿得到核心的 `Content-Length` 就是百分比，拿不到就是一条来回滑动的「不确定」条。
- 字体 Press Start 2P 通过 `<link>` 在运行时加载。这里刻意没用 `next/font`（它会在构建时下载字体，无网络环境下会让构建直接失败）；加载失败时优雅退化为等宽字体，不影响功能。
- 存档和「历史」都放在 IndexedDB 里；拿不到 IndexedDB 时（隐私模式等）「历史」会空着、载入过的游戏也不留痕，此时点「存档」会自动降级为下载 `.state` 文件。历史只占几百字节一条（纯字符串），存档仍是 Blob。
- ~~只支持桌面端~~：2026-10-13 起**取消了那个「请用桌面端」的提示**，窄窗口照画屋子 —— 尺寸链会自动收（屏幕取 `min(档位上限, 100vw − 360px)`，桌面 / 底座 / 吊灯线都跟着推出来），所以任何宽度下机身都不会再被 `main` 的 overflow 从两边切掉。窗口小于 900px 时那两处入口收进菜单抽屉，见上面「隐私政策与服务条款」。
- 联机要求双方都能访问公共 MQTT broker（默认 `broker.emqx.io`），**完全断网的内网用不了**。没有房间列表——房间码只能口头或手动传递。玩什么由房主决定，加入者只收画面、不能自己换游戏。详见上面的「联机」一节。
- **压缩包**：内层拆得出单机 ROM（`.nes` / `.smc` / `.pbp` 等）的 **zip 和 7z** 会按 ROM 走（7z 走 `public/compression/extract7z.js`，EmulatorJS 那份 asm.js，解大包要十几秒、接在下载进度条上），其余 zip 一律当街机 romset。**`.rar` 仍然不支持**——要解压得再引一套 wasm（EmulatorJS 那边是自托管的 unrar 241 KB），认出来时按键说明弹窗会给一句准话。
- **PS1 只认单文件光盘镜像**（`.pbp` / `.iso` / `.img` / `.chd`）：`.cue` + `.bin` 那种多文件形态直接拖进来表达不了（一次只能拖一个文件），**装在压缩包里则支持**（见上）。`.chd` 从 2026-10-19 起确认可用（核心带 libchdr）。另外 PS1 是**软件渲染 + 单线程 WASM**，3D 游戏（铁拳 3 这种）的实际流畅度得看机器 —— **这一项没实测过**。
- **PS1 的 `L3` / `R3` 和类比摇杆用不了**：键位模型只有 14 个钮（`ButtonName`），没有「摇杆按下去」这两颗；**类比摇杆本身也根本没建模**（键盘没有轴，手柄左摇杆推过阈值只当方向键用）。绝大多数 PS1 游戏十字键就能玩，但**必须用摇杆的那几款（《捉猴啦》这类）玩不了** —— 已知缺口，不是 bug。取舍理由见上面「键位」一节。
- **地板那台 MP4 的曲子不由仓库提供**：`public/audio/i-miss-you.mp3` 是一首有版权的录音制品，要自己放进去。文件不在时**自动退到现场摇的 8-bit 小段**（`lib/chiptune.ts`，运行时手搓一段 1.3–3.8 秒的 WAV；只在五声音阶里随机游走，旋律原创、和原曲无关）—— **每点一次都摇一段新的**，那一段**放一遍就停**，console 里留一行说明。兜底只退一次，刷新页面才会重新先试那个文件。
