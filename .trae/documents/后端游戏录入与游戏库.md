# 后台游戏录入 + 前台游戏库

## Context（为什么做）

当前项目是**纯前端**：ROM 只能由用户本地拖入，浏览器 IndexedDB 存一份卡带架，没有服务端、没有 API 路由、没有 `.env`。
本次要新增一条完整的**服务端数据链路**：

1. **后台录入**：登录后上传游戏（图片 + ROM）与元数据，落到 Cloudflare R2（文件）+ D1（元数据）。
2. **前台游戏库**：网页上新增「游戏库」按钮，全屏弹窗列出已上传的游戏，点一个即从服务端拉取 ROM 并直接开始玩。

基础设施（已提供）：

- R2 S3 端点：`https://02a52e16b5681706e785f920fe5443e7.r2.cloudflarestorage.com`，桶名 `games`
- R2 公网读取域名：`https://games.retrogamesonline.fun`
- D1 数据库 id：`9ab0a67e-b4dc-4c7f-bdcb-8ee1ded8ffc4`

**硬约束**：所有凭据（R2 密钥、CF API Token、会话密钥）只存在于服务端环境变量，绝不出现在 `NEXT_PUBLIC_*` 或客户端代码里；前端一律通过本项目 API 访问数据。

## 一、技术选型

| 事项 | 方案 | 理由 |
| --- | --- | --- |
| D1 访问 | Cloudflare D1 REST API（`api.cloudflare.com/client/v4/accounts/{acc}/d1/database/{id}/query`） | 不绑定部署环境，本地/任意托管都能跑；凭据仅服务端 |
| R2 上传 | `@aws-sdk/client-s3`（S3 兼容 + SigV4） | R2 的 S3 API 需签名，手写易错；只在服务端用 |
| R2 读取 | 服务端代理 `/api/games/[id]/rom` 流式回源公网域名 | 规避浏览器 CORS、隐藏真实来源、保住原始文件名 |
| 会话 | HttpOnly 签名 Cookie（Web Crypto HMAC-SHA256） | 无额外依赖；`middleware` 在 Edge 运行，用 Web Crypto 才能验签 |
| 口令哈希 | Node `crypto.scryptSync`（登录路由跑 Node runtime） | 无额外依赖 |
| 前台 UI | 复用 `ConsoleScene` 现有浮层面板模式（存档/联机/按键三个面板） | 与既有风格一致 |

新增依赖：`@aws-sdk/client-s3`（dependencies）。

## 二、数据模型（D1）

新建 `db/schema.sql`（同时作为手工建表参考）：

**games**
- `id` TEXT PK（uuid）
- `title` TEXT NOT NULL — 游戏名（必填）
- `image_url` TEXT NOT NULL — 图片公网 URL（必填）
- `rom_url` TEXT NOT NULL — ROM 在 R2 的对象 key（必填）
- `rom_name` TEXT NOT NULL — **原始文件名**（关键：FBNeo 靠 zip 文件名认驱动，必须保留原名）
- `console_type` TEXT NOT NULL — `nes` / `snes` / `arcade`
- `language` TEXT、`series` TEXT、`year` INTEGER、`developer` TEXT
- `created_at` INTEGER NOT NULL

**users**
- `id` TEXT PK
- `username` TEXT UNIQUE NOT NULL
- `password_hash` TEXT NOT NULL（`salt:hash`，scrypt）
- `created_at` INTEGER NOT NULL

建表语句通过 D1 REST API 执行（可由初始化脚本跑一次）。

## 三、服务端模块（新增 `lib/server/`）

- `lib/server/d1.ts` — D1 REST 客户端：`query<T>(sql, params)`，读 `result[0].results`，失败抛出。
- `lib/server/r2.ts` — S3Client 工厂 + `uploadObject(key, body, contentType)` + `publicUrl(key)`。
- `lib/server/session.ts` — `signSession(payload)` / `verifySession(token)`（Web Crypto HMAC）、Cookie 名 `nesload_admin`。
- `lib/server/users.ts` — `findUser(username)`、`verifyPassword(user, plain)`（scrypt 比对）。
- `lib/server/games.ts` — `listGames()`、`getGame(id)`、`insertGame(record)`。

均**不含** `'use client'`，只在服务端导入。

## 四、API 路由

| 路由 | 方法 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| `app/api/admin/login/route.ts` | POST / DELETE | 否 | 登录（校验 users 表 → 下发签名 Cookie）/ 登出 |
| `app/api/admin/games/route.ts` | POST | 是 | 接收 `multipart/form-data`：校验必填 → 上传 R2 → 写 D1 |
| `app/api/games/route.ts` | GET | 否 | 前台游戏库列表（id/title/imageUrl/consoleType/language/series/year/developer/romName） |
| `app/api/games/[id]/rom/route.ts` | GET | 否 | 按 id 查库 → 服务端回源 `R2_PUBLIC_BASE/rom_url` → 流式返回 |

上传校验：`title`、`image` 文件、`rom` 文件三项必填；`console_type` 必须∈枚举；`year` 可空数字。
R2 key 采用 `images/{id}-{safeName}` 与 `roms/{id}-{safeName}`（保留扩展名，`rom_name` 另存原名）。

**`middleware.ts`**：matcher `['/admin/:path*','/api/admin/:path*']`，放行 `/admin/login` 与 `/api/admin/login`，其余校验 Cookie 签名，失败重定向 `/admin/login`（API 返回 401）。

## 九、验证方式

- `pnpm typecheck` 与 `pnpm lint` 通过。
- 跑一次建表脚本，D1 中 `games` / `users` 表存在。
- 用 `scripts/create-user.mjs` 建管理员，`pnpm dev` 后：
  - 未登录访问 `/admin` → 跳登录页；登录后可进。
  - 上传一盘 NES（图片 + ROM + 必填项），返回成功；D1 有记录、R2 `images/` `roms/` 有对象。
  - 缺任一必填项 → 明确报错。
- 前台：点「游戏库」→ 弹窗列出该游戏 → 点它 → 电视出画面（NES/SFC 走 CDN 核心；街机走 `public/cores/`）。
- 校验凭据不泄露：`grep -r "R2_SECRET\|CF_D1_API_TOKEN"` 只在服务端文件出现，构建产物里无明文。
